\section{Architecture and Design Decisions}
\subsection{Hosted application}
Figure~\ref{fig:component} shows the browser, web boundary, account middleware,
business routes, request-selected private storage and optional providers.
FastAPI serves both the built React application and the API. This is a
same-origin web application, not the previous unauthenticated shared CSV service.

\begin{enumerate}
\item \textbf{Identity before storage.} Every private API request resolves a
verified account cookie before selecting a server-owned account directory.
Client project identifiers are checked within that account.
\item \textbf{Request-local binding.} Context variables hold the identity and
dataset adapter only for that request. Private data selection never mutates
global CSV paths. Initialization and blocking I/O use the thread pool.
\item \textbf{Durable, bounded single-host storage.} Each account uses SQLite
plus a cooperative file lock. The design does not assume a distributed database,
ephemeral filesystem or multi-host lock service.
\item \textbf{Explicit persistence and processing.} Translation/chat results
remain transient until saved. File previews do not approve or save terms.
Provider processing is labelled and bounded; local exact lookup avoids it.
\item \textbf{Recoverable replacement.} Revision restore is version-checked.
Workspace restore validates first, creates a safety backup and commits logical
rows only after safe media staging.
\end{enumerate}

\subsection{Deployment topology}
Figure~\ref{fig:deployment} shows a user's browser reaching an HTTPS reverse
proxy. All paths reach one FastAPI/Uvicorn application on loopback or a
firewalled private interface. The operator preserves the public Host and
forwarded protocol/client identity, and configures trusted proxy addresses.
Arbitrary internet clients must not supply trusted forwarding headers.

The backend serves \nolinkurl{frontend/dist}. Vite is optional during development,
not the production static host. Local testing uses the one-origin launcher and
loopback HTTP. Production requires a real HTTPS origin, SMTP, built assets and
mandatory authentication; docs/OpenAPI are disabled.

Private storage must be persistent, outside the public web root and restricted
to the service/operator account. Backups on that disk are not disaster recovery.
Off-host recovery must include the identity database and configuration under
separate protection, not only user-downloadable workspace ZIPs.

\subsection{Preserved compatibility boundary}
The desktop collector, compiler and academic export modules remain in source.
Without a hosted adapter, dataset functions still use the legacy CSV/audio
locations. The business factory defaults to authenticated operation and refuses
academic routes in that mode. Archive fixtures explicitly disable authentication;
production forbids doing so. No legacy profile, identity, CSV row or screenshot
is assigned to a new account.

\section{UML Conventions and Class Coverage}
The inventory covers \textbf{75 authored production classes}: 73 Python class
declarations, the generated lexer \texttt{Token}, and the TypeScript
\texttt{ApiError}. Tests, maintenance tools, external framework types and erased
TypeScript interfaces are not counted. Eleven class views distribute these
classes into readable responsibility groups.

\begin{itemize}
\item Hollow triangles point to base classes. Dotted realization arrows point
to a protocol contract; they do not claim Python nominal inheritance.
\item Plain associations describe actual references or nested values and show
multiplicities. Inheritance and module dependencies do not have cardinalities.
Nested JSON alone does not establish exclusive lifecycle composition.
\item Rectangles marked function/module/hook are not invented runtime classes.
Framework types and cross-view references are marked explicitly.
\item Every displayed synchronous or awaited message has an explicit receiver
activation and matching dashed reply. Callers remain active while awaiting
results. Actor activations represent participation, not CPU execution.
\item Use-case include arrows point to mandatory reused behavior; extend arrows
point toward the base use case. Activity branches use exclusive guards.
State views represent logical editor/device states, not nonexistent enums.
\end{itemize}
The checker validates inventory completeness, per-view declarations, sequence
activation balance, atlas mapping, rendered-image fingerprints and PDF layout
logs. It is not a general UML theorem prover or substitute for design review.

\subsection{Account and web classes}
Figure~\ref{fig:class-accounts} separates deployment settings, persistent identity
operations, public identity data and validated request DTOs. \texttt{AuthStore}
retains one settings object; identity DTOs are returned from SQLite rows rather
than retained in a fictional object aggregate. Request subclasses reuse
\texttt{AuthInput}'s extra-field rejection. The web middleware retains the next
ASGI application, while the log filter removes sensitive query values.

\subsection{Private storage and recovery classes}
Figure~\ref{fig:class-workspaces} shows \texttt{WorkspaceStore}'s structural
conformance to \texttt{DatasetStorage}. One selected store retains one file-lock
object; its tables persist values, not live request-model instances.
\texttt{HistoryInput} holds exactly one of translation or conversation content
and checks that the alternative agrees with its kind. Conversations contain
1--100 messages. Project/revision/backup input classes share explicit validation
rather than bypassing storage checks during recovery.

\section{Identity and Request Boundary}
\subsection{Email accounts}
Figure~\ref{fig:sequence-account} separates registration, email verification,
password sign-in and a later private mutation. Passwords use Argon2id.
Verification/reset tokens and session values are random and stored as hashes.
Email tokens are single-use with one-hour expiry; sessions expire after seven
days. Password reset revokes every existing session.

Account emails contain a link with the token in a URL fragment and require an
explicit confirmation button. GET navigation alone does not consume it.
Development writes an access-restricted \texttt{.eml} outbox. Production rejects
that mode and uses SMTP STARTTLS. Delivery failures are reported, not relabelled
as successful mail delivery. The outbox must never be publicly served.

Private mutations require a configured Origin and session-specific CSRF header.
Identity/rate storage failures produce safe errors. Persistent anonymous,
account and email/IP limits bound requests; user/global daily AI counters are
charged only at actual provider attempts. Exact local lookup remains available.

\subsection{Google identity}
Figure~\ref{fig:sequence-google} models the authorization-code flow with PKCE.
The server stores expiring state, browser binding, verifier and nonce. The
callback consumes matching state and verifies the ID-token signature, issuer,
audience, expiry, nonce and verified email against Google's signing keys.

Google subject identity is distinct from an email address. An email collision
with a password account requires password sign-in and explicit linking.
Unconfigured Google access is not displayed as a functioning sign-in method.
Automated tests use signed synthetic tokens and a mocked provider; real Google
consent/domain configuration is an operator acceptance gate.

\subsection{Browser state}
\texttt{AuthGate} renders no private pages until a session is resolved. CSRF and
project state remain in memory; neither tokens nor private content are stored in
localStorage. Cross-tab notifications contain a random change marker only.
Account changes refresh the session and clear private transient UI.

Project switching and sign-out confirm loss of drafts/recordings before
remounting the application. The API helper rejects responses from an older
account/project generation both before and after parsing their bodies. It does
not retry a mutation under a newly signed-in identity.

Request hooks suppress duplicate in-flight mutations. After a successful
settings/history mutation, read refresh explicitly cancels an older read first:
otherwise a pending read could discard the required refresh and hide a new
backup. Errors after interrupted mutations state that completion may be uncertain.

\section{Data Model and Transaction Boundaries}
\subsection{Identity and private workspace databases}
\begin{longtable}{L{3.0cm}L{11.4cm}}
\toprule\textbf{Storage} & \textbf{Responsibility}\\\midrule\endhead
\nolinkurl{auth.sqlite3} & users, sessions, email tokens, OAuth state and
persistent rate counters. No browser-selected user directory.\\
projects & Stable project ID, name, creation time. General is permanent.\\
entries & Entry ID, project reference and validated fourteen-field JSON record.\\
revisions & Project/entry IDs, action/time and before/after JSON. Recorded with
the terminology change in the same transaction.\\
history & Project, kind, title, bounded content, creation and update timestamps.
Saved only by explicit user action.\\
meta & Workspace version and owner-scoped backup catalog, schedule/state and
preview metadata. Backup restore replaces logical data, not every metadata key.\\
audio & Validated generated filenames. An entry refers to at most one recording;
several historical revisions may refer to that same immutable file.\\
backups & Manifest-verified ZIPs and bounded, expiring preview files.\\
\bottomrule
\end{longtable}

SQLite enforces project references; parameterized queries scope records to the
selected project. Per-account file locks coordinate cooperating writers across
processes. They are not protection against manual operator edits or a malicious
filesystem administrator. Private directories reject link/reparse-point paths.

Normal mutations preserve IDs and provenance. Duplicate normalized text within
one language is rejected. Entry evidence changes invalidate approval unless the
exact new fields are explicitly reviewed. Current-project statistics do not
count other users or reference-dictionary rows.

\subsection{Project and revision semantics}
Projects are per-account; current project selection is request-local.
Project management and full-account backups deliberately use account scope,
so deleting a formerly selected project does not lock the owner out of recovery.
Projects containing entries, saved work or revisions cannot be deleted.

Revision restore acquires the account lock, checks the workspace version,
validates required media and duplicates, then saves the recovered term with
\texttt{unreviewed} status and another revision. Revisions are not a regulatory
tamper-proof audit ledger: the operator controls the database and restoring an
earlier workspace replaces logical revision history.

\subsection{Audio publication}
Recording remains in the browser until an explicit upload. Upload validation
checks bounds, filename/type and content. A newly staged attachment is published
with the terminology update under the storage lock; failure cleans only that
new file. Existing committed recordings are retained for recovery.

There is no single database transaction covering all filesystem operations.
Logical rollback and careful staging provide a narrower, explicit guarantee.
A disk fault during cleanup must be surfaced rather than claimed to undo an
already committed change. Physical microphone/speaker behavior needs real-device
acceptance beyond mocked failures and synthetic audio streams.

\section{Language and Import Workflows}
Figure~\ref{fig:use-case} presents business goals, not academic roles. Visitors
and owners describe session states; there is no shared-team authorization model.
Optional AI suggestions extend translation only when enabled and needed.
Cloud transcription extends preview only with explicit consent.

Figures~\ref{fig:sequence-translation}, \ref{fig:sequence-chat},
\ref{fig:sequence-imports} and \ref{fig:sequence-dictionary} describe the
domain interactions after authenticated project binding. Dataset reads in the
hosted path delegate to the current private SQLite store. References are
read-only resources with source provenance, not approved private entries.

Exact whole-entry evidence is used without Gemini when unambiguous. Provider
requests receive only bounded selected evidence, never the full workspace,
contributor identities, arbitrary notes or stored audio attachments. A
consented media import is a separate provider request. Output remains a
suggestion requiring human review.

Source extraction occurs on the application server. Raw import files are
temporary; preview content is transient until the user explicitly saves reviewed
terms/results. Browser dictation/read-aloud is separate and may contact
browser-vendor services. Source permissions, sensitive-data handling and
translation/transcription quality remain owner responsibilities.

\section{Backup and Recovery Design}
\subsection{Snapshot format}
A ZIP contains \nolinkurl{workspace.json}, managed \nolinkurl{audio/...} and
\nolinkurl{manifest.json}. The manifest maps every payload member to its SHA-256
digest. The logical export includes all projects, entries, history and revisions.
Passwords, sessions, Google/Gemini credentials and server settings are excluded.

Validation rejects unsupported paths, duplicates/case collisions, linked or
encrypted members, inconsistent hashes, malformed records, invalid media and
missing recordings referenced by current or historical records. Archive, expanded
size and count limits apply before publication or replacement. SHA-256 detects
changes but does not authenticate an archive's source.

\subsection{Preview and replacement}
Figure~\ref{fig:sequence-backup} and activity Figure~\ref{fig:activity-restore}
make the destructive boundary explicit. Preview stores an account-scoped token,
counts and current version for one hour. Restore requires literal
\texttt{REPLACE}, revalidates the archive and refuses stale versions.

Before replacement the server creates a verified safety backup. New audio is
staged immutably; name collisions with different content receive fresh names and
all restored references are updated. Only then does one version-checked SQLite
transaction replace logical rows. Failed staging/commit removes only new files.
Previously committed files and the safety copy remain.

Successful replacement consumes the preview and resets the browser to General.
Post-commit cleanup errors are explicit and may leave the browser uncertain:
inspect saved state instead of repeating restore blindly. Reused or expired
tokens cannot apply the same destructive operation again.

\subsection{Scheduling and operations}
Automatic backups are opt-in at 24-hour or 168-hour intervals. Maintenance
checks each minute while the server runs, records attempts/errors and keeps
1--10 automatic copies. Manual and safety copies are not pruned automatically.
A storage-scan failure is logged and a later cycle still runs.

Same-disk copies do not meet disaster-recovery needs. Operators must agree
retention, free-space alerts, off-host consistency, access permissions, encryption,
recovery-time and recovery-point objectives. Account identities require a
separate complete-data-root backup. The release does not invent those objectives.

\section{Verification, Limitations and Handover}
Automated checks combine real SQLite/cookie/account behavior, mocked external
services, synthetic recordings, delayed-request regressions and real browser
downloads/restoration. In particular they cover account/project isolation,
password-reset revocation, CSRF, malformed Google identity, backup tampering,
stale versions, missing historical audio, rollback and maintenance retry.

The full-stack suite uses a new, isolated temporary data directory, local
development email and disabled provider configuration. It does not contact
Google/Gemini or use physical hardware. Tests do not populate real business
content. The verification register distinguishes current observations from
previous-version counts and unexecuted remote CI.

Before launch, the owner supplies infrastructure and real mail/OAuth/provider
configuration, approves content rights and retention/terms/support, evaluates
language quality and physical accessibility, agrees performance/recovery
targets and authorizes publication. No synthetic benchmark certifies an 8 GB
reference machine or an unspecified hosted traffic level.
