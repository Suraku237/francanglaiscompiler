\projectcover{Software Design Description}
{Public analysis. Immutable tests. Read-only reference resources.}
{Source-grounded design of the final Camfranglais compiler workspace.
The public application requires no account and retains completed analysis tests.
Collection, saved grammar and existing recordings are protected from public edits.
Retained operator/desktop code is distinguished from active public functionality.
Software behavior and collection review flags do not certify human fieldwork.}

\section{Document Status and Design Scope}
\subsection{Baseline and audience}
This design describes source revision \texttt{a1b88aa}, reviewed for the final
documentation on 27 September 2026. It is intended for implementers, reviewers
and the server operator. Dated corpus, test and deployment observations are
identified explicitly; neither a source revision nor a diagram proves that a
new release has been installed on the public server.

The application is a deterministic lexical/CFG workbench, not an identity
portal, chatbot, translation generator or generic dashboard. Its five navigation
pages are \textbf{Franc Analyzer}, \textbf{Analysis}, \textbf{Collection},
\textbf{Dictionary} and \textbf{Synthetic examples}. The current UI's Analyze
action records a complete public test. Reference browsing, text handoff and
recording playback do not add Collection entries.

\subsection{Three explicit application modes}

\texttt{require\_auth=None} &
Default public mode. Installs public-access policy, shared storage, read routes
and analyzer-test append. Uses \texttt{ServerSettings}; does not install
authentication, workspace management, import, coursework or backup APIs.\\\addlinespace
\texttt{require\_auth=True} &
Explicit retained authenticated API. Installs legacy identity and maintenance

The design assumes the normal \texttt{include\_academic=True} factory setting.
Disabling academic routes also disables the bootstrap's saved-test capability;
the current five-page frontend deliberately requires that capability. Optional
factory flags are not a promise that the same UI works in every maintenance
configuration.

\subsection{Evidence and provenance boundary}
The observed Collection contains 13 entries: 12 supplied sentences and one
word, with 20 retained revisions. The classified source has 878 supplied
vocabulary rows; merging distinct legacy senses produces 938 Dictionary
entries. There are 26 clearly labelled synthetic examples. These are distinct
populations, not 938 collected statements or 26 additional field observations.

The original 28 saved tests were preserved. A 26 September local observation
found 29 after an additional public test had been recorded. Read-only public
browser captures on 27 September show 34 saved tests and 13 Collection entries.
Counts grow with use; none of these dated totals is a permanent application
constant. Tests may include repeated text and rejected results and are separate
from Collection and the report's fixed twelve-case evaluation.

Human collection location, date, consent and transcription authenticity have
not been confirmed. The historical \nolinkurl{compiler/parser/yaounde.py}
filename identifies an implemented case-set grammar, not independently verified
fieldwork in that location. Original statements, including unresolved forms,
must not be silently corrected to improve acceptance statistics.

\section{Architecture and Decisions}
\subsection{System composition}
Figure~\ref{fig:component} separates the browser, FastAPI boundary, deterministic
compiler functions and protected persistence. FastAPI serves the built React
application and API on the same origin. The production host uses a reverse
proxy; Vite is a development tool, not the production web server.

Most behavior is implemented as Python module functions and React function
components/hooks. The class model therefore documents actual data models,
storage/policy objects, compiler helper classes and retained desktop classes.
It does not turn functions into invented controllers, services or repositories.

\subsection{Decision record}
\begin{enumerate}
\item \textbf{Public access without a fabricated identity.}
An opaque browser cookie and CSRF token protect submissions, but neither is an
account. The stable internal public actor UUID supports saved-test idempotency.
No fake user row, account counter or registration step is introduced.
\item \textbf{One shared dataset, narrower public writes.}
\texttt{PublicWorkspaceStore} extends \texttt{SharedWorkspaceStore}, which extends
\texttt{WorkspaceStore}. The public subclass permits only a new analyzer test.
It rejects Collection/grammar/recording mutations, existing-test writes and
imports. Hiding a button is not the enforcement mechanism.
\item \textbf{Deterministic and inspectable results.}
Regex/lexicon rules, explicit CFG transformations and a bounded predictive
parser produce token tables, sets, conflicts and traces. No provider decides
acceptance, generates a voice or writes coursework.
\item \textbf{Snapshot evidence rather than mutable saved results.}
Each recorded test stores its exact text, grammar source, lexer/parser results
and grammar analysis. Reopening a test does not rerun it against today's
Collection or grammar. Public append does not imply public update or deletion.
\item \textbf{Two meanings of acceptance remain separate.}
Vocabulary approval rejects exactly inputs with \texttt{UNKNOWN} tokens.
CFG acceptance separately reports whether the token-category stream can be
parsed by the submitted saved grammar. Neither is a judgement about a speaker.
\item \textbf{Compatibility is preserved, not advertised as active UI.}
Private accounts, old workspaces, saved histories, coursework archives and
desktop recording code remain. Their classes are covered, but their private
routes and legacy workflows are not presented as public features.
\end{enumerate}

\section{Public Request Boundary}
\subsection{Bootstrap, not login}
On startup, \texttt{PublicSession} calls
\nolinkurl{GET /api/public/session}. The successful default response contains
\texttt{access\_mode=public\_read\_only}, a \texttt{csrf\_token}, and capabilities
\texttt{analyze=true}, \texttt{save\_tests=true},
\texttt{edit\_collection=false}, \texttt{edit\_grammar=false} and
\texttt{edit\_recordings=false}. The frontend validates this contract before
rendering \texttt{App} and stores the CSRF token only in its API module state.
Figure~\ref{fig:sequence-public-session} shows this interaction.

The \nolinkurl{camfranglais_public} cookie is an opaque random value, not an
identity. It has \texttt{HttpOnly}, \texttt{SameSite=Lax}, \texttt{Path=/} and,
in production, \texttt{Secure}. The server reuses a valid cookie and replaces
an invalid or missing value. It derives a CSRF token and compares tokens in
constant time. No email address, display name or signed-in identity is created.

All four allowed POST paths require an allowed \texttt{Origin}, the public
cookie and \texttt{X-CSRF-Token}. In production the allowed origin is the
configured public HTTPS origin. Development adds explicitly configured local
origins. Route payload validation and domain bounds are additional checks, not
replacements for Origin/CSRF validation.

\subsection{Forbidden, absent and throttled requests}
Figure~\ref{fig:sequence-public-boundary} distinguishes the outcomes:
\begin{itemize}
\item Public writes targeting Collection, grammar or recordings return
\textbf{403}. The store also rejects forbidden writes and all imports.
\item Authentication, workspace management, coursework, imports, backups,
legacy history and restore endpoints are unavailable publicly:
\textbf{404}, not an account challenge or an HTML SPA success response.
\item A wrong Origin or invalid/missing CSRF on an allowed POST returns
\textbf{403} before domain work.
\item The shared limiter permits 120 requests per 60-second IP window.
Exhaustion returns \textbf{429} and \texttt{Retry-After}. The counter is in
\nolinkurl{public-access.sqlite3}, separately from \nolinkurl{auth.sqlite3}.
\end{itemize}

The public limit covers permitted API requests other than health; static
requests and preflight handling are not counted by this path. Shared-storage
lock timeouts return a busy response rather than silently bypassing the lock.
Unexpected storage failures are reported without returning private paths or
account records.

The historical \texttt{X-Mboa-Project} header and \texttt{project} query parameter
are validated if supplied, but they do not partition the public workspace or
select another account. The current frontend has no project selector.

\section{Analysis Recording, Retry and Reporting}
\subsection{Successful append}
Figures~\ref{fig:activity-analysis} and~\ref{fig:sequence-analyzer-test} specify the
normal path. The route uses \texttt{course\_operation}, which holds the
context-bound dataset lock around the saved-grammar check and recording work.
This prevents a concurrent cooperating writer from changing the referenced
revision halfway through the operation.

\begin{enumerate}
\item Compare the submitted canonical grammar with the saved profile's grammar.
The request-local public flag activates this restriction.
\item Look for an earlier request mapping for the stable internal public actor.
If one exists, compare exact input text and stored grammar source before reuse.
\item Analyze the grammar, read Collection and build the reviewed-word lexicon.
Run deterministic lexical analysis and predictive parsing.
\item Construct and validate a \texttt{RecordedTest}. Matching-entry metadata is
derived from exact text equality, not a fuzzy claim that the test was collected.
\item Generate the actor-scoped UUID5 identifier. The shared store authorizes a
new analyzer-test write, inserts the snapshot and request mapping in one
transaction, and increments the shared version.
\item Add response-only vocabulary approval and redacted ownership.
The original persisted \texttt{RecordedTest} remains unchanged.
\end{enumerate}

A valid analysis can retain a rejected parse. An invalid grammar or exceeded
grammar-analysis work bound raises an explicit validation error before snapshot
insertion. Public analysis never adds a Collection entry or modifies the saved
grammar. The non-persisting analysis endpoints remain distinct API contracts.

\subsection{Idempotency and stale grammar}
Figure~\ref{fig:sequence-test-retry} documents an important ordering detail.
\texttt{require\_shared\_grammar} normally rejects a changed submitted grammar
with 409 and reload guidance. When that request ID already exists, it allows
the recording function to perform its stricter exact-payload comparison.
Consequently:
\begin{itemize}
\item A new request with a stale grammar is rejected before analysis.
\item An existing request with identical text and grammar source returns the
original snapshot, even if a curator subsequently changed the saved grammar.
\item Reusing an ID with different text or grammar source returns 409 and never
overwrites the earlier result.
\item An ambiguous request mapping inherited from multiple former projects is
reported as a conflict rather than selecting an arbitrary old test.
\end{itemize}

In the browser, \texttt{pendingTest} keeps the UUID, input and grammar across an
uncertain retry. Success clears it. A later intentional Analyze click therefore
creates a new test even for repeated text. Editing the draft discards the old
pending retry key. Reloading the tab loses its unsent local draft/key but does
not erase a test already committed on the server.

Stopping the UI request, navigating away or reaching a timeout does not
guarantee server cancellation or rollback. The user is told to refresh Analysis
and inspect saved tests before assuming nothing was recorded.
Figure~\ref{fig:state-test} models these browser states without inventing a
runtime state-enum class.

\subsection{Snapshot invariants}
\texttt{SnapshotModel} uses strict validation and forbids extra fields.
\nolinkurl{LexicalSnapshot.consistent_statistics} checks statistics against its
stored token sequence. \nolinkurl{GrammarAnalysis.consistent_symbols} verifies
start/nonterminal/set consistency and refuses an LL(1) claim with conflicts.
\nolinkurl{ParseResult.consistent_outcome} relates acceptance to the absence of an
error. \nolinkurl{RecordedTest.consistent_consumption} checks consumed length and
requires an LL(1) grammar for an accepted parse.

These are real validation methods, not evidence that the DTOs are declared
frozen. Public immutability is enforced by route composition and store policy.
Figures~\ref{fig:class-analyzer-snapshots}, \ref{fig:class-lexical-statistics}
and~\ref{fig:class-grammar-results} expose the actual nested contracts.

\subsection{Analysis statistics}
The report traverses every retained test, holding only one full snapshot at a
time. It computes token/category counts, raw and normalized frequencies,
spelling variations, unknown-token review and recorded topic/language counts.
Only summaries are paginated; changing the page does not change the aggregate
population. An empty report has a null acceptance rate.

\texttt{summary} counts vocabulary acceptance; \texttt{grammar\_summary} counts
CFG acceptance. Each summary carries both results. Repeated intentional tests
count repeatedly; the system does not silently deduplicate an experiment.
Figures~\ref{fig:class-test-reports} and~\ref{fig:sequence-stats} show this design.
Collection entry/type/review counts are a different statistic.

\section{Deterministic Compiler Design}
\subsection{Automata and their implementation boundary}
Figure~\ref{fig:automaton-lexer} is an equivalent finite-state model of
\nolinkurl{TOKEN_SPLIT_RE}, not an invented lexer class. Double circles accept
a token form: \(W\) is word, \(I\) integer, \(F\) fraction, \(P\) punctuation
and \(O\) another character. Non-accepting states \(J\) and \(R\) require a
valid continuation after a joiner or decimal separator respectively.
Missing transitions enter an omitted dead state.
The scanner retains the last accepted prefix and resumes at the unconsumed
character; whitespace is skipped between matches.

The word class \(C\) is the Unicode regex class
\texttt{[\textasciicircum{}\textbackslash W\textbackslash d\_]}, not only ASCII
letters. In particular, U+02BC belongs to \(C\), so it follows word edges
rather than competing with the pending-joiner edge. This distinction preserves
the actual regex behavior and the diagram's determinism. Classification by
lexicon and morphology remains a later operation.

Figure~\ref{fig:automaton-parser} shows finite control for the LL(1) pushdown
recognizer. Its stack initially holds the end marker and start symbol.
One table entry replaces a top nonterminal with a reversed right-hand side;
a matching terminal is popped; an epsilon production consumes no category.
Acceptance requires the bottom marker and end-of-input together, not an
arbitrary empty stack or any recognized vocabulary.

The family \(q[a]\) encodes a single lookahead in finitely many states. The
diagram buffers a category on its input edge; the implementation instead
reads \nolinkurl{categories[position]} and advances its position only when
matching a terminal. This is an equivalent recognition model, not a claim
that the Python function declares those control states. Input validation,
non-LL(1) rejection and resource/repetition guards additionally bound the
actual implementation. The project has not implemented an LR automaton.

\subsection{Lexical pipeline}
The lexer first segments raw input using a compiled regular expression.
Internal apostrophes and hyphens remain part of words; a final non-whitespace
fallback preserves unsupported input for classification rather than dropping it.
Token text retains its original spelling.

\texttt{classify\_token} applies structural regex rules, validated reviewed-word
overrides, explicit existing lexicons, the supplied classified reference,
additional French forms and finally documented morphological guesses.
Multiple supplied categories yield \texttt{AMBIGUOUS}. Unsupported tokens yield
\texttt{UNKNOWN}. Case/apostrophe normalization is used for lookup, not as a
replacement for the displayed input.

Code-mixing annotations track compatible language evidence rather than
arbitrarily assigning one language to every ambiguous word. Sentence-ending
punctuation resets the run; unknown words carry no language evidence.
Verb/slang phrase matches retain raw, source-ordered spans and do not collapse
the parser's token sequence.

The learned map comes from approved lexical annotations, not from every saved
test. Known slang and supplied vocabulary are not rejected merely for being
nonstandard French or English. \texttt{VocabularyApproval.from\_statistics}
rejects exactly a positive \texttt{UNKNOWN} count; this also means that zero
tokens alone do not imply a vocabulary rejection. CFG behavior is separate.

\subsection{Grammar and predictive parsing}
The grammar reader validates explicit category-level notation. Productions are
lists of symbols; an empty right-hand side represents epsilon. The transformation
pipeline performs bounded ordered substitution, direct left-recursion elimination
and factoring with before/after steps. It then computes FIRST, FOLLOW and the
predictive table.

Conflicting table cells are omitted from the unambiguous table while all
competing productions remain visible in \texttt{conflicts}. Remaining recursion
or table conflicts prevent predictive acceptance. The parser never selects a
conflicting production arbitrarily. Its trace records stack, remaining
categories and action before each action; the rightmost stack symbol is the top.
\texttt{\$} denotes end of input, not an ordinary input word.

Figure~\ref{fig:sequence-compiler} shows the real function calls. The parser is
bounded to 256 tokens, 1000 characters per token, 2000 trace steps and 1024 stack
symbols. It also detects repeated stack/input configurations. A bound violation
produces a specific rejected parse, not an unbounded loop.

The generic teaching starter in \nolinkurl{compiler/parser/service.py} has an
immutable JSON analysis cache decoded for each request. This is not the current
saved assignment grammar in \nolinkurl{compiler/parser/yaounde.py}; custom/saved
grammars are analyzed afresh. The public client may use only the saved shared
grammar, subject to the existing-retry exception already described.

\subsection{Supplied case interpretation}
The exact twelve fixtures in \nolinkurl{compiler/tests/yaounde_cases.py} yield
ten accepted parses and two rejections at token 6 in the supplied evidence.
The unresolved forms \texttt{n'ais} and \texttt{alli} are preserved, not corrected
to force twelve successes. These results characterize this lexer/grammar/case
set; they neither prove universal Camfranglais validity nor authenticate the
statements' human collection provenance.

The shared root is not selected from an arbitrary browser path. A store object
holds paths and a file lock; it does not retain a collection of live
\texttt{RecordedTest} or \texttt{ProjectProfile} objects. SQL rows are validated
into values when read. Class associations therefore do not pretend that database
rows are in-memory object compositions.

\subsection{Request-local consistency}
\texttt{use\_workspace} binds the same shared store to dataset, coursework and
ownership ContextVars and resets the bindings on exit. Concurrent requests do
not reassign a process-global CSV/profile directory. A store's file lock
serializes cooperating shared operations, while SQLite transactions protect
logical row changes and version increments.

Public ownership always serializes as \texttt{owner\_id=null},
\texttt{owner\_name=""}, \texttt{can\_edit=false}. This is not a claim that every
field of every public record is anonymous: original statement text, contributor
context and other Collection metadata can still be public. Users are explicitly
warned not to submit personal or confidential content in publicly retained tests.

\subsection{Private maintenance and compatibility}
The default lifespan may start \texttt{maintain\_backups}. Each cycle checks
private schedule metadata; automatic backup is disabled by default and runs
only when configured and due. The shared maintenance store uses
\texttt{system=True} and a separate internal system actor. It is not the public
store and not a public administrator account.

The backup builder collects logical data and safe audio, checks referenced
media, constructs a checksum manifest, validates the resulting archive and
publishes it atomically before registering success. Failures are logged and
reported through private state; they are not silently called successful
backups. Figure~\ref{fig:sequence-backup} shows the configured background path.

Shared exports use document format 5, with format-4 compatibility. Base private
workspace export uses format 3; older private formats 1 and 2 normalize during
validation. The enclosing ZIP manifest remains format 1. These are retained
format contracts, not publicly downloadable reports.

Figure~\ref{fig:activity-restore} covers the explicit private restore procedure:
bounded archive validation, authorization, expiring preview, version check,
verified safety snapshot, staged media and transactional logical replacement.
A non-system shared restore cannot alter another creator's records, request
history or original archived profiles. The public subclass rejects every import.
A post-commit cleanup error does not prove that the logical transaction rolled
back; recovery must inspect saved state rather than retry blindly.

Audio staging and SQLite are coordinated but not one filesystem-wide ACID
transaction. A workspace ZIP does not recreate identities or protected server
configuration; operator disaster recovery must preserve those separately.
The optional desktop collector and retryable recorder remain documented in
Figures~\ref{fig:class-domain} and~\ref{fig:state-audio}, without being confused
with public browser functionality.

\section{Deployment, Trust and Operational Limits}
\subsection{Target host topology}
Figure~\ref{fig:deployment} specifies the intended Ubuntu 24.04 VPS at
\texttt{109.199.120.38}. Source and built assets live at
\nolinkurl{/var/www/francanglaiscompiler}; persistent data at
\nolinkurl{/var/lib/camfranglais}; restricted environment configuration at
\nolinkurl{/etc/camfranglais.env}. The \texttt{camfranglais.service} systemd
service runs as the \texttt{camfranglais} user.

The application listens on private loopback \texttt{127.0.0.1:2021}.
Nginx serves ports 80/443 with TLS at
\url{https://camfranglais.duckdns.org}. Port 2021 is not a public application
URL. Proxy trust must be limited to the controlled reverse proxy so scheme,
client address, secure-cookie policy and rate-limit keys remain meaningful.
Private data/configuration must not be placed under frontend static assets.

\subsection{Production settings and readiness}
\texttt{ServerSettings} validates environment, absolute data directory and
public origin. Public production requires a non-loopback HTTPS origin and a
built frontend. SMTP and Google configuration are unnecessary for this default
mode. \texttt{AuthSettings} inherits these settings and adds retained identity
requirements only for the explicitly selected authenticated mode.

The web boundary applies API no-store behavior, content/type/frame/referrer
protections, a same-origin CSP, URL/body bounds and production HSTS/host/TLS
handling. A broad legacy microphone permissions-policy allowance is not proof
that a public microphone control exists. Public mutation denial must be tested
at the server, not inferred solely from UI screenshots.

Read-only checks on 27 September confirmed HTTPS bootstrap 200 with
\nolinkurl{access_mode=public_read_only} and the expected capabilities. The
deployed interface opened directly into the five public pages without login;
the genuine report screenshots retain that observation. This supersedes the
older 26 September bootstrap-401 observation.

The documentation session did not perform a remote update or verify the
operator's exact deployment steps. The diagram's internal host configuration,
backup recovery and long-term availability are not certified by a browser
capture. Full deployment acceptance must still exercise the expected allowed
and denied routes and operational recovery, not health alone.

\subsection{Failure and resource behavior}
General API JSON bodies are bounded to 1 MiB in the web boundary; analyzer
grammar/input contracts and parser work bounds impose tighter semantic limits.
Pydantic rejects extra or inconsistent snapshot fields. Lock contention,
missing media, malformed grammars, stale revisions, expired previews and
rate-limit windows have explicit failure responses or private operational
errors, rather than fabricated successful outcomes.

The application is a durable single-host design, not a horizontally distributed
database service or end-to-end encrypted corpus. Server operator access and
off-host recovery remain trust concerns. CSRF tokens protect browser submissions
against cross-site requests; they do not turn public tests into confidential data.
