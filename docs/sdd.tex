\section{Architecture and Decision Record}
\subsection{Default product}
Figure~\ref{fig:component} maps the implemented components.
\nolinkurl{backend.main.create_app} defaults to authenticated operation with
compiler/coursework routes enabled. FastAPI serves the built React application
and API on one origin. The product reuses its actual lexer, grammar analysis,
predictive parser, corpus analysis and draft export; it does not replace those
features with a generic dashboard.

Generation modules, keys/models/timeouts/quotas and translation/chat/suggestion/
explanation endpoints are removed. Health returns \texttt{status=ok} and
\texttt{mode=compiler}. Google OAuth and SMTP are retained identity/account-mail
facilities. The \nolinkurl{httpx} dependency remains needed by Google code/key
exchange; its presence is not evidence of an active AI provider.

\begin{enumerate}
\item \textbf{Evidence before conclusions.} Raw manual text remains distinct
from glosses, references and constructed examples. The default CFG is
illustrative until the group justifies it from real statements.
\item \textbf{Deterministic language processing.} Regex/lexicon rules classify
tokens; explicit CFG algorithms produce transformations, sets/table and traces.
No provider determines acceptance or writes the group's discussion.
\item \textbf{Identity before storage.} A verified session supplies the
server-owned account directory. Project selectors are validated within that
account, never treated as arbitrary filesystem paths.
\item \textbf{Dual request-local binding.} Dataset and coursework dispatch
through separate protocols backed by the same selected \texttt{WorkspaceStore}.
No global CSV/profile path is reassigned for a web request.
\item \textbf{Explicit persistence.} Previewing, inspecting examples or
running analysis does not silently save or approve field statements.
Screenshots and profile changes require deliberate actions.
\item \textbf{Recoverable compatibility.} Existing accounts, recordings and
legacy saved histories remain. Workspace format 2 adds coursework/screenshots,
while format-1 restoration remains supported.
\end{enumerate}

\subsection{Deployment and trust boundary}
Figure~\ref{fig:deployment} shows one durable application host behind an HTTPS
reverse proxy. Private SQLite/audio/backup paths are outside public static
assets and restricted to the operator/service account. Local development uses
loopback and, by default, a private email outbox. Production requires HTTPS,
real SMTP, secure cookies, trusted hosts/proxy headers and mandatory authentication.
Vite is an optional development server, not the production web host.

The application is not a stateless multi-host database service and account
isolation is not end-to-end encryption. Off-host recovery must preserve identity
data and protected configuration as well as workspace data. A per-account ZIP
does not recreate authentication identities.

Text extraction and compiler execution occur on the application server.
There is no generative provider, OCR, remote transcription or browser dictation
integration. Optional browser read-aloud is not evidence processing. The UI
selects only voices that the browser reports as \texttt{localService}, and
refuses read-aloud when none is suitable rather than choosing a remote fallback.
Voice availability/locality reporting belongs to the browser/OS and is not an
application-level guarantee of every underlying network behavior.

\subsection{Explicit legacy boundary}
The desktop collector remains production source, so its real classes and selected
workflows are still documented. Its CSV/audio path is a compatibility workflow,
not the default authenticated product. Unbound coursework functions can access
legacy profile/screenshot files only in the explicit no-auth maintenance context.
The factory rejects \texttt{require\_auth=False} in production.
New private accounts never adopt the old CSV, author identities or screenshots.

\subsection{Exact class scope}
The checked inventory \nolinkurl{docs/diagrams/class-coverage.json} enumerates
all authored production Python/TypeScript classes. It includes private classes,
protocols and the lexer \texttt{Token} generated by \texttt{namedtuple}.
It excludes tests, maintenance tools, external framework classes and erased
TypeScript interfaces.

Function modules, hooks, grammar dictionaries, table rows, screenshots and
parse steps are not promoted into invented runtime classes. Selected methods
are actual source operations; DTO serialization/validation inherited from
Pydantic is identified as inherited behavior. The frontend's authored
\texttt{ApiError} is distinct from its function components.

\begin{itemize}
\item Hollow triangles point to base types; dotted realization arrows point
to structural protocol contracts, not nominal Python inheritance.
\item True nested/stored references have multiplicities. Inheritance,
realization and module dependencies do not receive decorative cardinalities.
Reusable DTO references are not exclusive-lifecycle compositions.
\item Every displayed sequence communication has an active sender, an explicit
receiver activation and a matching reply/deactivation. Actors are active while
participating; this does not claim CPU execution by people.
\item State diagrams describe actual logical GUI/recorder states, not nonexistent
enums. Activity decisions have exclusive guards; human assignment tasks are labelled.
\item Full-size atlas images are embedded without squeezing complex graphs onto
A4. Figures and their source filenames remain traceable.
\end{itemize}

\section{Accounts, Request Selection and Isolation}
Figure~\ref{fig:class-accounts} documents \texttt{AuthSettings}, \texttt{AuthStore},
identity/input/error models and web-boundary classes. The store retains one
settings reference; it returns identity values from SQLite rather than maintaining
a fictional aggregate of live user DTOs. Passwords use Argon2id and session/
verification/reset values are stored as digests.

Figure~\ref{fig:sequence-account} separates registration, email verification,
sign-in and a later authenticated mutation. Private routes require a valid
session; mutations additionally require allowed Origin and session-specific CSRF.
Request throttles remain, but generation quotas do not. Blocking identity/storage
work is dispatched off the event loop.

Optional Google authorization uses PKCE, browser-bound state, nonce and signed
identity-token validation (Figure~\ref{fig:sequence-google}). Invalid/replayed
state cannot authorize an exchange. A token-exchange failure does not trigger
the signing-key request. Equal email alone does not link an existing password
account; signed-in explicit linking is required. Logs describe safe failure
stages without leaking codes, tokens, credentials or provider response bodies.

\subsection{One request, two storage adapters}
Figure~\ref{fig:sequence-storage} makes the key isolation decision explicit:
\begin{enumerate}
\item Middleware resolves \texttt{UserIdentity} and validates the requested
project within that user's workspace.
\item The context factory initializes \texttt{WorkspaceStore} in a worker
thread and binds the workspace ContextVar.
\item \nolinkurl{dataset.use_storage(workspace)} and
\nolinkurl{coursework_store.use_storage(workspace)} bind both adapters.
\item Routes call normal dataset/coursework functions; protocol dispatch uses
the selected account/project store.
\item Context tokens are reset on exit, including exceptions. Invalid selection
does not fall back to global legacy files.
\end{enumerate}
Native screenshot/audio URLs carry a project query parameter because they
cannot always attach the application's project header. The server still derives
the account solely from the cookie, not from that query.

Saving a profile validates its grammar before upserting JSON. A missing profile
returns a new default at the coursework layer, with three blank member strings
and the illustrative grammar; it is not automatically persisted or marked genuine.
Screenshot/profile records also prevent deletion of a supposedly empty project.
No original account or private data migration/deletion is part of this change.

\subsection{Screenshot pipeline}
Figure~\ref{fig:sequence-screenshot} follows actual upload and byte retrieval.
The route allows a 3 MiB JSON request body to carry base64; the generic JSON cap
remains 1 MiB. The request model bounds the name/data URL. The store validates
base64, PNG/JPEG content, a 2 MiB input and 12-megapixel resolution, then converts
to PNG and again rejects a normalized result over 2 MiB. Storage validates that
PNG before inserting it under an account lock and transaction.

The returned URL includes the selected project. Reads query both image ID and
project ID in that authenticated account's SQLite database, return image bytes
with private/no-store and nosniff headers, and do not reveal a legacy filesystem
path. Deletion has the same project condition and increments the version.
Image decoding cannot establish that the student supplied a genuine capture.

\subsection{Document format and verified restore}
Workspace document \textbf{format 2} includes \texttt{coursework} and
\texttt{screenshots} arrays. Validation checks project references, unique IDs,
record bounds, profile schema/grammar and decoded PNG data. A legacy
\textbf{format-1 workspace document} is copied and normalized to format 2 with
empty coursework/screenshots. The enclosing ZIP \textbf{manifest remains format 1}.
These version numbers describe different layers.

Figures~\ref{fig:sequence-backup} and \ref{fig:activity-restore} show preview,
integrity/schema/media validation, expected-version checking and the pre-restore
safety snapshot. A profile/image mutation after preview invalidates that version.
Media is staged without overwriting colliding committed files; logical rows
are replaced transactionally after validation. Failed staging/commit removes
only newly staged files. A post-commit cleanup failure is explicit and does not
mean the committed database automatically rolled back.

Checksums detect changed bytes, not trusted authorship. Backups preserve all
private projects, coursework, screenshots and recordings but not identity secrets
or server settings. They are separate from the coursework deliverable bundle.

\section{Manual Collection, References and Local Imports}
\subsection{Raw evidence and annotation}
Figure~\ref{fig:class-collection} separates editable entry inputs, stored-entry
DTOs, read-only dictionary values, metadata/health and explicit errors.
Raw \texttt{StoredText} fields preserve observed spelling/whitespace and reject
blank-only content. Stored glosses and notes also retain their exact input.
The existing \nolinkurl{ShortText} validation trims leading and trailing
whitespace from supplied contributor and source-location values on create/edit.
Import previews and frontend handoffs preserve those provenance values before
this save-time normalization. Omitted patch fields and existing records are not
rewritten by that rule.

ID, timestamp and attachment operations are not freely
editable request fields. Duplicate entries and stale IDs are errors rather than
silent replacement. Evidence changes invalidate approval unless explicitly
reviewed as the new evidence.

The assignment target counts Sentence entries, not Word/Phrase annotation rows.
Corpus analysis can inspect all saved entries; this does not inflate the
10--15-statement target. Suggested topic gaps are for discussion and remain
review items, not a mandatory one-statement-in-every-topic gate.

\subsection{Source-labelled learning material}
Figure~\ref{fig:sequence-dictionary} loads validated versioned references and
returns paginated search results with filename/line and competing senses.
The 179 source rows are not 179 unique words or manually collected statements.
English meanings and etymological origins do not supply reviewed French glosses
or part-of-speech labels.

The 26 supplied practice statements are explicitly constructed.
\texttt{PracticeEntry.constructed} is always true. Reading either source never
inserts it into the empirical corpus. Authenticity remains the responsibility of
the group, not a side effect of a search result or parse success.

\subsection{Bounded server-side extraction}
Figure~\ref{fig:class-import-coursework} contains \texttt{ImportEntry} and
\texttt{ImportPreview}; the latter is local-only. No suggestion request/result
models or provider choices remain. Figure~\ref{fig:sequence-imports} separates
file preview from an explicit reviewed save.

The upload must contain exactly one file and no cloud-consent fields. Supported
formats are UTF-8 TXT/Markdown/CSV/JSON, DOCX and text-layer PDF. Local extraction
is bounded to 12 MiB input, 40,000 characters, 40 PDF pages and 100 structured
drafts. DOCX ZIP/XML and PDF safety checks apply before returning text.
Unsupported media, encrypted/invalid documents and image-only PDFs are rejected,
with no OCR/transcription fallback.

Partly scanned PDFs may return readable text with warnings; students must
compare the complete source. Structured imports keep allowed raw/provenance
fields without trimming contributor/location values, but cannot import approval.
Only the later collection save applies short-metadata normalization; statement
text, glosses and notes remain exact. Preview does not retain the original file
as an attachment or save entries automatically.

\section{Deterministic Compiler Design}
\subsection{Lexer and report}
Figure~\ref{fig:class-compiler} identifies real runtime classes and function
modules. The generated \texttt{Token} holds raw text and category; API
\texttt{TokenResult} values are shown in Figure~\ref{fig:class-api-results}.
The individual \texttt{AnalyzeRequest} preserves text and rejects blanks
(Figure~\ref{fig:class-api-requests}).

The lexer splits raw tokens with regex, applies structural number/punctuation
rules, then considers explicitly approved, unambiguous language-labelled Word
annotations, small base lexical lists, morphological heuristics and UNKNOWN.
Sentence rows are not training data. Conflicting annotations cannot silently
choose one category. Multiword verb/slang patterns and code-mixed transitions
are separate annotations, not claims of a complete multilingual model.
Structural and multiword regexes are precompiled. Matching respects token
boundaries, preserves raw spelling and returns phrase occurrences in source
order; multiword annotations do not collapse the token stream.
For example, the brief's illustrative \emph{drop me} phrase remains separate
underlying tokens, rather than being replaced by one VERB terminal to force
parser acceptance. Such an illustration is not a collected field statement.

Corpus reporting computes raw statements/tokens, token and category frequencies,
unknown counts and normalized spelling-variation candidates. Case/accents are
used for comparison without rewriting original wording. Variation grouping is
orthographic, not proof of shared meaning; \texttt{\_LIKE} categories are
heuristic guesses, not certified POS.

\subsection{Grammar and predictive parser}
Figure~\ref{fig:sequence-compiler} traces the shared corpus and single-input path.
Grammar notation is read and validated, supported direct/indirect left recursion
is removed, common prefixes are factored, and each changed stage retains bounded
before/after evidence. FIRST/FOLLOW are computed to a fixed point and the LL(1)
table records conflicts rather than silently picking one candidate.

The parser consumes category labels, not a probabilistic sentence meaning.
A bounded stack machine records pre-action stack/input/action traces, matches
the end marker and reports accepted/error/consumed results. Residual recursion,
conflicting tables, invalid grammar and excess work are explicit boundaries.
LL(1) is the implemented alternative; there is no LR/SLR implementation claim.

One corpus analysis reads a bounded selected-project snapshot (at most 500
entries and 100,000 characters), analyzes the submitted grammar and parses each
entry. Single-input parsing uses the same selected project's reviewed word map.
The coursework operation holds the same reentrant account workspace lock used
by mutations across profile/corpus/screenshot reads and analysis. Cooperating
account mutations therefore cannot mix evidence revisions within the operation.
Analysis does not implicitly save the editor/profile.

\notice{Interpretation boundary}{
A grammar can accept a constructed sentence or reject genuine speech.
Neither result establishes authenticity or linguistic correctness.
The default CFG remains an illustration until the group relates its rules to
real observations and explains coverage, ambiguity and rejection.}

\subsection{Optimization evidence}
Only the public illustrative starter grammar (including its saved stripped
form) is cached as immutable JSON. Each caller receives newly decoded mutable
results. Custom grammar text/comments, corpus statements and reviewed word
annotations are not retained by that grammar cache.

Algorithmic changes must preserve deterministic outputs, trace semantics and
caller isolation. Any timing claim belongs with its actual fixture, warm-up,
sample size, environment and exclusions.

The source-hash-verified record
\nolinkurl{compiler/output/benchmark_verified.json}, recorded
22 September 2026 at 09:46:18 UTC on Windows 11 / AMD64 / CPython 3.14.6,
contains thirteen individual synthetic cases and a separate paired comparison.
It uses 21 samples of 150 iterations and reports five warm-ups per case;
each sample is a batch-average timing, not individual request latency.
The paired batches alternate order in one process and compare the same current
grammar preparation algorithm on the exact whitespace-stripped public starter.

This is a narrow cache benefit for repeated public-starter preparation,
\textbf{not} a speedup claim for custom grammars, every compiler algorithm,

captures were different-time runs with substantial timing noise and include
unchanged or slower cases; they remain historical comparisons, not proof that
all operations improved. No account/project data was used in the synthetic
benchmark. The current record's eleven source hashes were checked against
the implementation before documenting these values.

\section{Coursework Evidence and Draft Deliverables}
Figure~\ref{fig:activity-analysis} places human collection and interpretation
around implemented analysis steps. Three distinct nonblank names, authentic
manual-transcription confirmation, collection method, grammar rationale and
discussion are explicit profile data, not hidden generated content.

Figure~\ref{fig:sequence-coursework} separates saving a submitted profile snapshot
from exporting saved evidence. The frontend must not mark later edits saved
when an older request completes. Unsaved profile/screenshot work is finished
before the explicit export. The backend uses saved profile/corpus/images and
current deterministic analysis to assemble:
\begin{itemize}
\item A \textbf{DRAFT} printable HTML report with 25 sections and missing-input
markers, not a certified 25-page finished report.
\item Editable PowerPoint slides and timing notes totaling ten minutes:
three per member and one shared minute.
\item Raw dataset, token, frequency, variation and acceptance CSV; grammar,
lexical specification, parser cases, profile and checklist JSON.
\item Genuine supplied screenshot PNGs, relevant source snapshots and
own-corpus regression cases.
\end{itemize}

The coursework ZIP does \textbf{not} contain raw recordings. Full workspace
backups preserve recordings together with coursework. The shared reentrant
account lock protects profile data, corpus rows and screenshot reads throughout
export and analysis. This provides a coherent saved-evidence snapshot against
cooperating workspace mutations.
This is not a transaction over developer-edited source files or arbitrary
external filesystem writers. Source snapshots omit environment secrets but raw
text/contributor metadata are included, so the archive must be shared only with
authorized course recipients.

Generated test expectations snapshot the parser's current decisions; they are
not independent proof that a linguistic judgment is right. The group must
review accepted/rejected cases, author original discussion, inspect genuine
screenshots and verify actual 25--30-page output, capped at 30. The SRS/SDD
PDFs are separate engineering documents and have no such report-page target.

\section{Frontend Boundaries and Compatibility Views}
Figure~\ref{fig:class-frontend} keeps React function components/hooks distinct
from the authored \texttt{ApiError} class. The API boundary attaches cookie,
CSRF/project selection and cancellation context; older identity/project
responses cannot overwrite a new session. Project switching/sign-out warns
before discarding dirty drafts. Local recording and optional read-aloud are
separate capabilities; neither is browser dictation.

Legacy history can be inspected/exported without sending data to removed
translation/chat endpoints. Retaining its schemas preserves old account data,
not a live generation feature. Figure~\ref{fig:class-services} shows the reduced
configuration class and actual function modules; no invented provider service
remains in the inventory.

\subsection{Why desktop diagrams remain}
The optional desktop collector is still authored production code. Its actual
\texttt{App}, \texttt{Tooltip}, \texttt{Recorder} and errors remain in
Figure~\ref{fig:class-domain}, with real selected operations and ownership.
It must therefore remain covered even though the authenticated compiler is the
default product. These diagrams are explicitly labelled \emph{desktop
compatibility}, never the current account/project storage flow.

\section{Validation, Measurement and Open Gates}
The existing local PlantUML/LaTeX build renders all current sources and compiles
atlas, SRS and SDD. The strict checker verifies exact production-class inventory,
mapped declarations, one source/image/sheet per diagram, correct SDD/atlas page
mapping, balanced call/reply activations, embedded image fingerprints and clean
layout/reference logs. It does not prove every UML semantic claim, so class
relationships and diagram scope also require source inspection.

Documentation-specific tests exercise missing/obsolete classes, runtime
TypeScript versus erased interfaces, generated namedtuple classes, pixel
normalization and invalid sequence activations. Final counts/results are
recorded in \nolinkurl{docs/README.md}; no prior suite totals are reused.

Backend/compiler tests and isolated browser fixtures establish software
behavior, not genuine fieldwork or public deployment acceptance. Historical
\nolinkurl{docs/evidence/*.json} remains unmodified. Prior Gemini, translation,
assistant, dictation and cloud-media acceptance has no bearing on the removed
architecture.

\notice{Open coursework gates}{
The reviewed corpus was empty. Genuine manual text, corpus-derived grammar
reasoning, authentic screenshots, original linguistic discussion, final
pagination and rehearsed delivery remain outstanding. No diagram, generated
draft or synthetic test is presented as their substitute.}
