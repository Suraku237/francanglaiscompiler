\section{Purpose and Document Control}
This SRS defines a web application for individual users who need translation,
terminology, document/audio processing and recoverable saved work. Each account
has its own private workspace; projects organize one owner's work. Local testing
exercises the same authenticated application intended for hosting.

Version 2.0 supersedes the local-only operating assumptions of version 1.3.
The earlier academic requirements and planning estimates remain in
\nolinkurl{docs/srs-legacy.tex}; they are not this release's business backlog,
acceptance evidence or user interface. No historical sprint is retroactively
declared completed. School identities and research records are not onboarding
data for hosted users.

The SDD describes source-grounded implementation and UML. The current
\nolinkurl{README.md} describes installation and operation. Reproducible
verification and remaining owner gates are recorded in
\nolinkurl{docs/README.md} and \nolinkurl{docs/evidence}.

\subsection{Status vocabulary}
\begin{description}[style=nextline]
\item[Implemented] Present in production source, with relevant automated
checks. This does not certify every deployment or external service.
\item[Automated evidence] A recorded test/build/measurement using stated
fixtures and environment, not a claim about real users or live language quality.
\item[Owner gate] Infrastructure, credentials, content rights, human evaluation
or a policy decision requiring the release owner.
\item[Excluded] No commitment to deliver that capability in this release.
\end{description}

\section{Product and Operating Scope}
\subsection{Users and services}
A visitor can register, verify an email, sign in or recover an account. A
signed-in owner manages only that owner's data. There are no shared-team roles,
cross-account projects, billing or in-app administrator console. The service
operator configures infrastructure and can access the underlying storage;
privacy is account isolation, not end-to-end encryption.

Supporting systems are SMTP for account emails, optionally Google for identity,
and optionally Gemini for generation/transcription. Browser speech services have
their own implementation-dependent processing boundary. The application does
not promise native Francanglais or Cameroon Pidgin voices.

\subsection{Business areas}
The application has seven areas: Translate, Assistant, Terminology, Dictionary,
Documents \& audio, History, and Workspace settings. It does not expose the
preserved compiler coursework pages or constructed-example library by default.
The standalone desktop collector and legacy global CSV remain separate.

\subsection{Languages and evidence}
French, English, Francanglais/Camfranglais and Cameroon Pidgin are supported
language directions, not interchangeable labels. The reference dictionary
contains 179 source rows with English meanings, including repetitions and
competing senses. It contains neither reviewed French glosses nor reliable
grammatical-category annotations. Approval of private terminology records the
owner's review, not expert certification or universal linguistic truth.

\section{Functional Requirements}
\begin{longtable}{L{2.0cm}L{12.4cm}}
\toprule\textbf{ID / area} & \textbf{Requirement and measurable acceptance}\\\midrule\endhead
\req{BR-01}{Accounts}
{Register with a valid email, display name and password of 12--128 characters.
Require email verification before password sign-in.}
{An unverified login is refused; verification consumes a single-use, one-hour
token. Registration never returns that token in the API response.}
\req{BR-02}{Sessions}
{Use server-validated cookie sessions, explicit sign-out, origin checks and
session-specific CSRF protection on authenticated mutations.}
{Private APIs return 401 without a valid identity. Wrong Origin or CSRF returns
403. Production cookies are Secure, HttpOnly and SameSite=Lax.}
\req{BR-03}{Recovery}
{Provide resend-verification and password-reset emails with generic public
responses; revoke all prior sessions after a successful password reset.}
{Expired/replayed tokens fail. Old credentials/sessions cannot access saved
work after reset. Email-service failures are explicit and retryable.}
\req{BR-04}{Google}
{Support Google authorization-code sign-in with PKCE, state, nonce and signed
identity-token validation when operator credentials are configured.}
{Wrong issuer/audience/expiry/nonce, replayed state or unverified email is
rejected. Matching email does not automatically link an existing password
account; explicit signed-in linking is required.}
\req{BR-05}{Isolation}
{Choose private storage using the authenticated, server-generated account ID.
Bind the selected project to the request, not process-global mutable state.}
{Two accounts cannot read, change, restore or download one another's terms,
saved work, media, backups or preview tokens. Parallel request tests remain isolated.}
\req{BR-06}{Projects}
{Create and rename private projects; retain General; permit deletion only of
empty projects without terminology, saved work or revisions.}
{A foreign project is rejected. Switching warns before discarding drafts.
The active project must be switched before its UI deletion; account-level
management remains available if a formerly selected project is removed.}
\req{BR-07}{Terms}
{Create, search, filter, edit and explicitly delete original expressions,
language, glosses and business metadata. Preserve identifiers and provenance.}
{Duplicates in the same language return 409. An evidence edit invalidates
approval unless the exact new evidence is explicitly reviewed. Failed saves
do not silently discard drafts or pretend success.}
\req{BR-08}{Translation}
{Prefer unambiguous whole-entry approved terminology and enabled reference
alignments. Label optional AI suggestions and their supplied evidence.}
{Exact dictionary lookup works without Gemini. Local ambiguity or missing
coverage with AI disabled returns an actionable error. Separate word matches
are not represented as a trustworthy full-sentence translation.}
\req{BR-09}{Assistant}
{Send an explicitly submitted message, bounded recent conversation and enabled
source evidence to the configured provider.}
{No request is sent on navigation or draft handoff. The provider never
automatically approves or saves its output as private terminology.}
\req{BR-10}{Dictionary}
{Search/paginate the supplied reference rows without mutating private
terminology. Retain source document/line and competing senses.}
{The 143 core and 36 supplementary rows remain separate references.
Source errors are explicit, not an empty successful dictionary.}
\req{BR-11}{Imports}
{Preview supported documents/media with bounded extraction. Require separate
cloud consent and an explicit preview for processing that needs AI.}
{Changing a file resets consent. Structured candidates remain unreviewed.
Selecting, previewing or handing off a passage never automatically saves it.}
\req{BR-12}{Recording}
{Record, stop, preview and download audio in supported browsers; upload only
through explicit save or consented import actions.}
{Permission denial and unexpected device stops are visible. Active recording
prevents save; failed publication cleans only new uncommitted media.
Typing remains available when recording is unavailable.}
\req{BR-13}{Saved work}
{Explicitly save translations/conversations in the current project. Provide
open, title search, rename, JSON download, draft reuse and deletion.}
{Reload preserves saved items, not unsaved drafts. Account/project changes
clear private transient UI and ignore late responses, including delayed bodies.}
\req{BR-14}{Revisions}
{Record terminology create/update/delete/restore events transactionally and
restore a selected revision using the current workspace version.}
{A changed workspace causes 409 rather than overwrite. A recovered entry is
unreviewed. A missing required recording or duplicate expression prevents restore.}
\req{BR-15}{Backups}
{Create, list, download and deliberately delete verified full-account ZIPs.
Include all projects, terms, revisions, saved work and managed audio.}
{Manifest, paths, counts, schema, media signatures and referenced files are
validated. Password/session databases and provider configuration are excluded.
A failed backup is not published as usable.}
\req{BR-16}{Restore}
{Preview an owner-scoped backup before replacement. Require literal REPLACE,
an unexpired token and the unchanged workspace version.}
{Create a verified safety copy first. Stage media without overwriting existing
files; commit logical rows in one transaction. Reject stale/unsafe archives.
Errors after possible commit explicitly advise inspecting saved state.}
\req{BR-17}{Scheduling}
{Offer opt-in daily or weekly backups with 1--10 retained automatic copies.}
{Check schedules each minute while the server runs. Preserve manual/safety
copies. Record per-workspace failures and retry subsequent cycles after
storage-scan failure; stopping the server stops scheduling.}
\req{BR-18}{Operation}
{Serve the built website and API on one origin through a single launcher.
Reject unsafe development exposure and incomplete production configuration.}
{One command starts both surfaces. Production requires HTTPS origin and SMTP,
forbids disabled auth/reload, requires built assets and disables API docs.}
\req{BR-19}{Usage controls}
{Bound request bodies, retained data and provider attempts. Keep local lookup
available when the daily AI allowance is exhausted.}
{Every actual outbound attempt, including retry, consumes user and global
allowance. Exact local results and missing-provider configuration consume none.}
\bottomrule
\end{longtable}

\section{Data and Retention Requirements}
\subsection{Authoritative storage}
The identity database contains accounts, hashed sessions, one-time tokens,
OAuth state and rate counters. Each account's workspace database contains
projects, entries, revisions, history and metadata. Audio and ZIPs live in that
same account directory. Server-generated identifiers and validation prevent
client-supplied account paths.

Private records use the same fourteen fields as the entry DTO. They include
identifier, text, entry type, French and English glosses, category, source
location, notes, audio filename, contributor, timestamp, language, review status
and lexical category. SQLite is authoritative for hosted records; the desktop
CSV is separate.

\subsection{Explicit bounds}
\begin{longtable}{L{6.2cm}L{8.2cm}}
\toprule\textbf{Resource} & \textbf{Limit}\\\midrule\endhead
Projects per account & 20, including General\\
Terminology / saved items / revisions & 10,000 / 500 / 20,000 per account\\
Saved conversation & 100 messages; each message at most 4,000 characters\\
Managed audio & 1,000 files and 128 MiB aggregate per account\\
Single import/audio upload & 12 MiB plus bounded multipart overhead\\
Document extraction & 40 PDF pages; 12 megapixels per image; 40,000 characters; 100 aligned draft records\\
Translation input & 4,000 characters\\
Backup archive & 32 MiB compressed; 160 MiB expanded; 1,002 members\\
Backup storage / previews & 512 MiB per account; at most three one-hour previews\\
General JSON request & 1 MiB\\
AI daily attempts (defaults) & 100 per account; 2,000 globally, including retries\\
\bottomrule
\end{longtable}
Exceeding a bound is an explicit failure, not silent truncation of saved work.
Limits are safeguards, not purchased storage entitlements or certified capacity.

\subsection{Retention and deletion}
Deleting a current record does not erase previous revisions or backup copies.
Committed media is retained for deliberate recovery; imports do not retain raw
uploaded files as a document library. A workspace restore replaces logical
content but does not replace accounts, quotas or credentials.

The owner must approve retention, deletion requests, off-host copies, legal
notices and support procedures before launch. There is no hidden assertion of
regulatory compliance or automated account-erasure workflow. These decisions
must precede any destructive retention automation.

\section{Non-functional Requirements}
\begin{longtable}{L{2.0cm}L{12.4cm}}
\toprule\textbf{ID} & \textbf{Requirement and acceptance boundary}\\\midrule\endhead
\req{NBR-01}{Privacy}
{Authenticate and authorize at the API boundary, not only by hiding UI. Use
bounded, parameterized storage operations and server-only secrets.}
{Cross-account integration tests cover IDs, projects, media, history, archives
and preview tokens. No real private dataset is used as a test fixture.}
\req{NBR-02}{Reliability}
{Surface invalid input, provider errors, storage failure and uncertain commits.
Use atomic publication and appropriate transaction/version checks.}
{Injected failures preserve prior logical data and committed media as specified.
Post-mutation refresh supersedes stale reads rather than dropping the refresh.}
\req{NBR-03}{Response time}
{Move blocking private-store initialization and provider-accounting I/O off
the ASGI event loop. Bound provider retries and UI request duration.}
{A thread-identity regression verifies off-loop initialization. Record timings
on the actual test host; do not claim an agreed public throughput/SLA without
load targets, deployment measurement and operator approval.}
\req{NBR-04}{Usability}
{Provide responsive desktop/mobile layouts, visible errors, explicit save/
delete/restore actions, keyboard focus management and accessible form names.}
{Desktop/mobile browser regressions exercise navigation, modal focus, review,
recording permission errors and account/recovery workflows. Physical devices
and assistive-technology acceptance remain human gates.}
\req{NBR-05}{Code quality}
{Keep typed frontend sources, reusable request/storage helpers, reproducible
builds, automated regressions and source-grounded documentation.}
{Type-check app and tests; build assets; verify class coverage, sequence
activations, atlas references and embedded PDF figure pixels.}
\req{NBR-06}{Deployment}
{Run on one durable host with restricted storage and an HTTPS reverse proxy.
Treat infrastructure monitoring and disaster recovery as explicit operations.}
{Validate production settings and headers in tests. Owner rehearses actual
host restart, email delivery, TLS, disk recovery and off-host restore. No
ephemeral-disk or multi-host clustering support is implied.}
\bottomrule
\end{longtable}

\section{Acceptance and Release Gates}
\subsection{Automated completion}
The release verification register must contain observed results, exact commands,
environment and limitations. Required checks cover Python domain/API/storage
regressions, frontend unit/component behavior, app/test TypeScript, production
build, mocked desktop/mobile scenarios and real local full-stack browser flows.
Local fake email, signed mock Google tokens, generated audio and mocked Gemini
responses must never be described as live-provider acceptance.

CI retains Windows Python 3.11 and 3.14, adds Linux server checks and real
full-stack browser flows, and verifies documentation. A local working-tree run
does not establish remote CI success; publication and a passing workflow remain
an explicit release gate.

\subsection{Owner-supplied acceptance}
\begin{enumerate}
\item Hosting account, public domain, TLS, durable disk, trusted-proxy settings,
service supervision, monitoring and off-host recovery destination.
\item Configure the SMTP sender and credentials, then verify actual delivery of
account messages. Configure the Google client, consent screen and authorized callbacks.
\item Gemini access/budget and authorized non-sensitive live trials, with human
review of translation/transcription quality and actual service errors.
\item Approved business glossary, reviewed French meanings and source-content
redistribution permissions.
\item Physical microphone/speaker, denied permissions, device disconnect,
browser-voice, real-device and assistive-technology acceptance.
\item Privacy/retention/terms/support, capacity and recovery objectives, change
publication and final launch approval.
\end{enumerate}

\subsection{Scope not silently added}
Billing, subscriptions, shared-organization permissions, fine-tuned language
models, certified legal/medical translation and distributed multi-host storage
are excluded. The earlier 8 GB reference-machine desktop performance target
is not met merely by measurements on a roughly 32 GB development machine.
It is retained as historical context, not an undisclosed hosted SLA.
