\section{Introduction and Document Control}
\subsection{Purpose, audience and revision}
This SRS specifies the implemented local Francanglais/Cameroon Pidgin platform,
its acceptance boundaries and remaining human deliverables. It serves contributors,
the three-person project group, learners, maintainers and reviewers. The SDD
explains the actual modules, all production application classes and UML workflows.

Version 1.3 retains v1.2's replacement of v1.1's desktop-only assumptions and
adds the separate supplied reference dictionary. Backend, compiler and
editable React source now provide direct evidence: the web API, reviewed
translation, import preview, grammar workbench and coursework export are
\emph{implemented}, not hypothetical components. Existing FR-01--FR-20,
NFR-01--NFR-12, US-01--US-16, PB-01--PB-16 and S1--S4 identifiers remain
traceable; revised acceptance wording corrects obsolete schema and UI details.
New scope receives new identifiers rather than rewriting sprint history.

invented. The illustrative default grammar is teaching material.

\subsection{Definitions}
\begin{description}[style=nextline]
\item[Entry] A stored word, phrase or sentence with original text, metadata and optional audio.
\item[Gloss] A supplied French or English meaning; optional, and not guaranteed correct.
\item[Approved] A local review flag, not an authenticated role, expert certificate or universal linguistic truth.
\item[Grounding] Deterministic retrieval of selected approved text/gloss alignments, not model training.
\item[LL(1)] A category-level predictive grammar using one lookahead token and an explicit end marker.
\item[Evidence coverage] Overlap with retrieved examples; it is not a translation accuracy score.
\item[Story point / task hour] Independent provisional planning estimates, not measured velocity.
\end{description}

\section{Overall Description}
\subsection{Implemented scope}
The desktop CustomTkinter collector and a FastAPI service share local UTF-8 CSV
storage. React/Vite supplies five web workspaces: Translator, Learning assistant,
Collection, Import \& learn and Compiler lab. A deterministic Python lexer and
bounded CFG/LL(1) parser run without an AI key. Exact unambiguous approved
full-entry translations also run locally. Optional Gemini calls provide
explicitly labelled translation/chat suggestions, media transcription and
compiler explanations; they do not decide parser acceptance or approve records.

The collector has Collect, Browse \& Edit and Stats tabs, optional microphone
recording, attachment and playback. The backend manages reviewed alignments,
validated CRUD, import previews, a three-member coursework profile, genuine
user-uploaded screenshots and a locally generated draft ZIP.

\subsection{Actors and operating boundary}
Contributor, maintainer, learner and reviewer are usage roles, not enforced
permissions. The application has \textbf{no authentication, authorization,
per-user storage, durable audit trail or public-hosting hardening}. Use a
trusted local workstation/loopback backend. CORS constrains browser origins;
it is not access control. A remote backend's ``local'' files reside on that
server, not automatically on the browser device.

Python and Tcl/Tk provide the desktop runtime; sounddevice, soundfile, NumPy
and usable devices are optional audio dependencies. FastAPI/httpx and the
compiler provide the API; React runs in the browser. Vite's development proxy
forwards \nolinkurl{/api} to the local backend. A deployed frontend requires
an equivalent same-origin API arrangement, not an assumed hosting service.
Browser dictation/speech synthesis are separate from desktop WAV recording.

\subsection{Explicit exclusions and honest limits}
No automatic fieldwork, speaker identity, consent verification, authentic
corpus population, trained unseen-word predictor or certified translation
accuracy is claimed. No database transaction spans CSV, audio, coursework
profile and screenshots together. Cooperative file locks prevent overlapping
application mutations, not manual editing races or last-writer-wins semantic
conflicts. Multi-user deployment, universal grammar coverage, LR/SLR parsing,
native Francanglais voices and provider retention guarantees are not supplied.

\section{Data and External Interface Requirements}
\subsection{Canonical storage and compatibility}
The header order is part of the contract. The SDD specifies the actual locks
and transaction boundary; the following is the logical schema, not an
invented persistence model class.
\begin{longtable}{L{4cm}L{10.3cm}}
\toprule\textbf{Field (in order)} & \textbf{Meaning}\\\midrule\endhead
\nolinkurl{id} & Generated stable identifier; historical desktop and full API UUID formats coexist.\\
\nolinkurl{text} & Collected wording. The API preserves stored strings; a new browser/desktop form trims surrounding whitespace.\\
\nolinkurl{entry_type} & Word, Phrase or Sentence; legacy values can remain on an unchanged row.\\
\nolinkurl{french_gloss}, \nolinkurl{english_gloss} & Optional alignments; no automatic correctness guarantee.\\
\nolinkurl{category} & Required topic selection on new UI/API entries; legacy values are retained where unchanged.\\
\nolinkurl{source_location} & Optional provenance/location, not a geolocation sensor or proof of permission.\\
\nolinkurl{notes} & Optional context, uncertainty and private review notes.\\
\nolinkurl{audio_filename} & Optional one-file reference; no file existence/ownership uniqueness constraint.\\
\nolinkurl{contributor} & Optional supplied text, not an account or mandatory matricule field.\\
\nolinkurl{timestamp} & Creation timestamp; desktop local and API UTC formats remain supported.\\
\nolinkurl{language} & francanglais, pidgin, mixed or unspecified. Unknown/legacy defaults to unspecified.\\
\nolinkurl{review_status} & unreviewed or approved. Unknown/legacy defaults to unreviewed.\\
\nolinkurl{lexical_category} & Empty or one of the eleven declared lexer terminals.\\
\bottomrule\end{longtable}
The 11-field pre-review schema is the canonical prefix ending at timestamp.
The 10-field legacy schema additionally omits source location. Exact header
order is validated; arbitrary columns and incomplete/extra cells are rejected.
Reads upgrade metadata in memory. Mutations write all fourteen fields atomically.

Topics are Taxi / Commuting, Internet Connectivity, Electricity Supply,
Market Bargaining, Rainy Season, Fuel Scarcity, Roadside Business,
Bendskin Communication, Security Checkpoint and Campus Life, plus Other.
They are \emph{collection categories}, not lexer terminal labels.

\subsection{Interface families}
All explicit application routes use \nolinkurl{/api}: health/metadata,
translation, chat, lexical analysis, dataset CRUD, read-only dictionary lookup, import preview/suggestions,
and coursework state, project saving, corpus analysis, parsing, tutoring,
screenshots and export. DTO details and the
complete method/path table are in the SDD. Request models reject unknown
JSON fields. The OpenAPI page is generated by FastAPI; it is documentation,
not proof that an AI key is valid. Desktop has no HTTP dependency.

\subsection{Privacy and evidence separation}
Local retrieval sends ID, expression text, language, French/English
glosses, match type and a source discriminator, with coverage where applicable.
Dictionary matches additionally include their supplied forms and reference
filename/line; these are not human fieldwork claims. Collection source location,
contributor, notes, timestamp, audio and full corpus are excluded. This
minimization does not anonymize sensitive words a user explicitly submits.
Cloud consent applies to import preview; pressing a later AI suggestion,
translation, chat or tutoring action is a separate submission. Browser speech
providers may receive audio independently of Gemini. The coursework export
\emph{does include} corpus text, contributor/provenance and the saved project;
it must be reviewed before sharing. These documentation PDFs contain neither
the actual corpus nor invented fieldwork.

\section{User Stories and Acceptance Criteria}
US-01--US-16 preserve the previous story identities. US-17--US-24 describe
already implemented added scope. Each maps to the corresponding PB suffix.
None of these statements records a historically completed sprint.

\story{US-01}{Initialize a usable corpus}
{As a contributor, I want safe initialization so I can resume collection without losing existing entries.}
{FR-01, FR-06; NFR-02, NFR-04}
{\item Missing storage gets a canonical header; supported existing storage survives a read byte-for-byte.
\item Corrupt or unsupported storage fails visibly instead of being replaced with an empty corpus.}
\story{US-02}{Capture an annotated example}
{As a contributor, I want exact text with optional meanings and context so that the record retains useful evidence.}
{FR-02--FR-06, FR-17, FR-22}
{\item Blank text is rejected; valid fields, generated metadata and language/review decisions round-trip.
\item Only a committed save resets the draft; genuine unknown facts can remain blank.}
\story{US-03}{Notice duplicate text}
{As a desktop contributor, I want advisory duplicate feedback so that legitimate repeated observations remain possible.}
{FR-07; FR-25 for the different web policy}
{\item Matching normalization includes case, whitespace, apostrophes and language.
\item The warning is debounced and non-blocking; web duplicates instead return 409.}
\story{US-04}{Find and select an entry}
{As a maintainer, I want search and a reliable selection so I can locate annotations for review.}
{FR-11, FR-25; NFR-10}
{\item Desktop empty/non-matching queries show all/no rows; selection uses the cached row.
\item Web filters apply to returned rows, while displayed aggregate counts remain whole-corpus counts.}
\story{US-05}{Correct an annotation}
{As a maintainer, I want controlled editing so that identity and omitted evidence stay intact.}

\subsection{Required fieldwork and group input checklist}
\begin{enumerate}
\item \textbf{Exact statements:} provide 10--15 genuinely heard, manually
transcribed sentence records, preserving wording, accents, code mixing,
ellipsis and uncertainty. Map them to the ten topics. Demo prompts, AI
translations, OCR and machine transcripts are not substitutes for listening.
\item \textbf{Provenance and meanings:} supply collection context/location,
collector and dates where genuinely known and permitted; record uncertainty.
Provide French/English meanings only when known or reviewed; otherwise leave
them blank. Use mixed/unspecified language labels when appropriate.
\item \textbf{Method and permission:} describe how/when/where collection
occurred, permission to record/process/share, anonymization and any
restrictions. Keep sensitive permission evidence in an appropriately
restricted place, not automatically in a public repository.
\item \textbf{Three actual members:} the first author's provided name/matricule
are already retained on the title pages. Supply the other two identities and all individual
contributions to collection, implementation, analysis, writing and presentation.
The profile has three free-text member slots, not separate verified identity
fields. Complete document title pages and contribution descriptions truthfully.
\item \textbf{Original interpretation:} write the group's grammar rationale,
findings on lexical variation/code mixing, discussion, limitations and
citations; link claims to collected IDs. Review parser rejections instead of
calling the speech wrong. Generated test expectations need independent review.
\item \textbf{Genuine demonstrations:} supply screenshots of actual work,
group acceptance, physical microphone/player and browser/device observations,
and separately authorized live-provider checks. Mark self-attestation only
when true; software cannot establish authenticity.
\item \textbf{Final submission:} review the actual coursework manuscript for
25--30 pages (maximum 30) and rehearse the 10-minute presentation, approximately
three minutes per member plus shared wrap-up. These SRS/SDD PDFs are supporting
engineering documents, not the required research report.
\end{enumerate}
