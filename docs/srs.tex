\section{Purpose and Document Control}
This SRS defines the externally observable behavior, constraints and acceptance
criteria of Camfranglais for the CS4110 Compiler Construction assignment,
Summer 2026, SET A. It is an implemented-product baseline, not a promise of a
general-purpose language understanding system. Requirements use ``shall'' for
the current product contract; unimplemented proposals are labelled explicitly.

The companion Software Design Description (SDD) explains the implementation and
contains source-grounded UML views. The UML atlas provides separately zoomable
diagram sheets. The final coursework report is a distinct 25--30-page document
containing the supplied corpus, calculations, test outcomes and genuine browser
captures. Its page limit does not apply to this engineering specification or
the SDD.

\section{Problem, Scope and Evidence}
\subsection{Educational problem}
Informal urban expressions can combine French, English, Pidgin, local slang,
nonstandard spellings and incomplete clauses. A conventional compiler's lexer
and parser provide a useful, inspectable model of selected structures, but
cannot establish a speaker's intended meaning, social context or authenticity.
Camfranglais therefore preserves raw input and exposes deterministic token
classification, grammar transformations, sets, table entries and parse traces.

\subsection{Current product boundary}
The active navigation contains exactly five destinations:
\begin{enumerate}
\item \textbf{Franc Analyzer}: type or paste a statement, then analyze and
publicly retain its original input and results.
\item \textbf{Analysis}: inspect immutable saved tests, vocabulary statistics,
separate CFG statistics, saved grammar and computed parser artifacts.
\item \textbf{Collection}: search and inspect existing entries, glosses,
annotations and available audio without modifying them.
\item \textbf{Dictionary}: search source-labelled reference vocabulary.
\item \textbf{Synthetic examples}: browse explicitly constructed practice
material, never automatically counted as fieldwork.
\end{enumerate}

Login, registration, recovery, Google identity, profiles, logout, project
management, public imports, microphone recording, grammar editing, administration,
history screens and in-app report/presentation generation are outside the active
interface. Translation/chat, OCR, automatic transcription, browser dictation,
speech synthesis and AI explanations are not features of this release.
Recorded read-aloud uses existing audio; it is not generated speech.

\subsection{Corpus and reference baseline}
The documentation snapshot contains 13 Collection entries: 12 supplied
sentences and one Word annotation. The supplied sentences contain 81 tokens.
The saved corpus-specific CFG accepts ten and rejects two, both at token six:
\texttt{n'ais} and \texttt{alli} remain \texttt{UNKNOWN}. These results do not
correct the original wording. The reference dictionary exposes 938 entries
derived from 878 supplied CSV rows plus retained distinct legacy senses.
Twenty-six synthetic examples remain a separate practice library.

These are dated observations, not hard-coded deployment limits. Public test
history grows independently of Collection: 34 saved tests were observed online
on 27 September. Repeated tests and older snapshots can produce totals that
differ from a one-pass evaluation of the twelve statements.

\notice{Fieldwork is not certified}{
The saved manual-transcription confirmation is false and the collection-method
field is blank. Some records contain location text or audio references; neither
proves when, where or by whom the original expression was heard. The documentation
must not invent collection dates, speaker identities, consent or authenticity.}

\section{Actors, Permissions and Operating Modes}
\begin{longtable}{L{3.0cm}L{6.6cm}L{4.6cm}}
\toprule\tablehead\textbf{Actor} & \textbf{Permitted actions} & \textbf{Restrictions}\\\midrule\endhead
Public visitor & View all public pages; analyze input; retain and inspect
immutable tests; play available recordings. &
No accounts, private user workspace, reference editing or public administration.\\\addlinespace
Student authors / examiner & The same public actions; use exported documentation
and source locally for coursework review. &
No elevated browser role is inferred from a name or matricule.\\\addlinespace
Deployment operator & Configure service, TLS, storage, backups and controlled
offline reference maintenance using filesystem/server access. &
Not an account role in the public application; maintenance endpoints are not
made public.\\
\bottomrule
\end{longtable}

The default factory mode, \texttt{require\_auth=None}, selects the public
read-only boundary. Explicit \texttt{True} retains the authenticated legacy
API for compatibility tooling/tests; it is not the deployed public API.
Explicit \texttt{False} is unrestricted local maintenance and is prohibited
in production. Historical classes and records remain in the repository without
implying that their interfaces are enabled.

Anonymous cookie and CSRF bootstrap is not authentication. It supplies
same-origin request protection, not user identity or access isolation. Public
test text is visible to other visitors; the UI shall warn against submitting
personal, confidential or sensitive material.

\section{Functional Requirements}
\begin{longtable}{L{2.0cm}L{6.1cm}L{6.1cm}}
\toprule\tablehead\textbf{ID / area} & \textbf{Required behavior} & \textbf{Acceptance criterion}\\\midrule\endhead
\req{FR-01}{Public entry}
{The application shall open directly into the five-screen workspace without
sign-in, registration, SMTP or an identity provider.}
{A fresh browser loads the analyzer and reference pages without an account.
There is no account gate or credential control.}
\req{FR-02}{Capabilities}
{Bootstrap shall report public access and allowed capabilities. Reference
mutations shall be denied by the server, not merely hidden.}
{Analyze/save are true; Collection/grammar/recording edit flags are false.
Reference mutations return 403; absent maintenance APIs return 404.}
\req{FR-03}{Input fidelity}
{The analyzer shall preserve original case, spacing, accents, apostrophes,
punctuation and mistakes in the saved input.}
{Normalization is limited to matching/statistics. Raw saved text is unchanged;
tokens retain original spelling. Empty input is a valid test request.}
\req{FR-04}{Lexer}
{The lexer shall segment with regular expressions, then classify deterministically
using structural rules, approved Word annotations, explicit word lists,
reference categories, French forms and morphological fallbacks.}
{Unsupported non-whitespace input remains represented as UNKNOWN.
Conflicting reference classifications produce AMBIGUOUS, not guessed context.}
\req{FR-05}{Language clues}
{Code-mixing clues shall compare French/English/Pidgin language-candidate sets
independently of token part-of-speech labels.}
{Unknowns carry no language evidence. Sentence-ending punctuation resets the
comparison. Output retains the original endpoint spellings.}
\req{FR-06}{Phrase annotations}
{Recognized multiword verb/slang expressions shall be additional source-ordered
annotations, not replacements for the original token stream.}
{Phrase boundaries exclude word-internal matches; absence of a phrase match
does not erase, merge or reject otherwise valid tokens.}
\req{FR-07}{Vocabulary verdict}
{Vocabulary approval shall reject exactly tests with one or more UNKNOWN
tokens. It shall remain separate from CFG acceptance.}
{Recognized slang, AMBIGUOUS and other known labels pass vocabulary approval.
Empty input has no UNKNOWN, but the saved corpus CFG still rejects it.}
\req{FR-08}{Saved grammar}
{New public analyses shall use the operator-saved grammar, displayed read-only.}
{A stale/different grammar on a new analysis returns 409 with a reload instruction;
the browser cannot submit an editable local draft as the shared grammar.}
\req{FR-09}{CFG transforms}
{The grammar service shall parse bounded notation, perform supported direct
and ordered indirect left-recursion elimination, then left-factor.}
{Each transformation records before/after rules and its operation.
Unsafe cycles, notation errors and excessive expansion fail explicitly.}
\req{FR-10}{Sets and table}
{FIRST/FOLLOW shall be computed to a fixed point, including epsilon and
end-of-input. The LL(1) table shall retain conflict diagnostics.}
{No conflicting production is silently selected. A residual recursive or
conflicting grammar disables predictive parsing.}
\req{FR-11}{Predictive parser}
{A bounded stack machine shall consume lexical categories using the LL(1)
table and expose stack, remaining input, action and consumed-token count.}
{The rightmost stack symbol is the top; snapshots precede the action.
Acceptance requires complete input consumption. Failure identifies the position.}
\req{FR-12}{Immutable tests}
{Analyze shall retain the input, grammar, lexical results, statistics,
approval and parser trace as one original test snapshot.}
{Refresh preserves tests. No public edit/delete route exists.
Later dictionary/grammar changes do not rewrite earlier results.}
\req{FR-13}{Retry semantics}
{A request UUID shall distinguish retrying a submission from intentionally
running a new test.}
{An identical retry returns the original record, including after an operator
grammar change. Conflicting reuse fails; a new completed test counts separately.}
\req{FR-14}{Statistics}
{Analysis shall aggregate original saved-test snapshots, including repeats;
Collection entries not tested shall not inflate these statistics.}
{Vocabulary and CFG totals are visibly distinct. Frequency case-folding and
orthographic variation rules are described; unknown counts remain explicit.}
\req{FR-15}{Collection}
{Visitors shall search/filter and view existing raw expressions, glosses,
annotations and available attachments read-only.}
{No create/edit/delete/import control is active. Existing raw text, revisions
and ownership are preserved in storage during the public-access upgrade.}
\req{FR-16}{References}
{Dictionary entries shall retain source/line, origin, part of speech and
distinct senses. Examples shall be clearly synthetic.}
{Search does not turn dictionary entries/examples into collected statements.
Ambiguous senses and reference-origin limitations are visible.}
\req{FR-17}{Recorded audio}
{Read-aloud shall look up and play only an existing compatible recording,
with an explicit unavailable state otherwise.}
{No TTS fallback, browser speech synthesis, voice cloning or public upload/
record/delete function is invoked. Playback failures are actionable.}
\req{FR-18}{Ownership privacy}
{Public responses shall redact historical ownership presentation without
altering stored owners. New tests use the internal public actor convention.}
{Public ownership is null/blank and cannot edit. No fake user account is
created. Existing credentials and archival records remain untouched.}
\req{FR-19}{Recovery boundary}
{Configured operator backup lifecycle shall continue privately. The release
shall preserve existing databases/media and immutable tests.}
{Backup/restore/admin APIs are not mounted publicly. Operators verify protected,
database-consistent backups and rehearse restoration in isolation.}
\req{FR-20}{Documents}
{Source-grounded SRS/SDD/UML and a separate 25--30-page coursework report
shall be supplied in editable form and PDF.}
{All production classes have UML coverage; sequence activations balance;
current images are embedded; PDF references/layout pass the strict checker.}
\bottomrule
\end{longtable}

\section{Quality Requirements and Failure Contracts}
\begin{longtable}{L{2.4cm}L{11.8cm}}
\toprule\tablehead\textbf{ID} & \textbf{Requirement and verification boundary}\\\midrule\endhead
\textbf{QR-01}\newline Correctness &
The same bounded input, grammar and lexicon snapshot shall yield the same
compiler output. Tests shall exercise actual source sentences and independent
boundary cases. Passing a small corpus is not an accuracy benchmark.\\\addlinespace
\textbf{QR-02}\newline Durability &
SQLite transactions and coordinated locks shall protect shared snapshots.
Persistence failures shall never be presented as successful saves. Browser
cancellation does not guarantee that the server cancelled an in-flight save.\\\addlinespace
\textbf{QR-03}\newline Public safety &
HTTPS, trusted hosts/proxies, body limits, same-origin CSRF, secure production
cookies, rate limits and security headers shall remain. These controls do not
make public submissions private or constitute an abuse-proof system.\\\addlinespace
\textbf{QR-04}\newline Explainability &
The UI and report shall distinguish vocabulary recognition, grammar fit,
heuristic language evidence, supplied glosses and verified facts. No generated
meaning or hidden correction may substitute for a failed analysis.\\\addlinespace
\textbf{QR-05}\newline Accessibility &
Keep labelled controls, keyboard navigation, visible errors, focus management,
responsive layouts and text alternatives to audio. Tests on selected desktop/
mobile browsers do not certify all devices or assistive technologies.\\\addlinespace
\textbf{QR-06}\newline Maintain\-ability &
Use the existing Python/TypeScript test suites, source-labelled references,
local PlantUML renderer and LaTeX pipeline. No online renderer receives project
code or private records. Historical evidence is preserved with its original date.\\\addlinespace
\textbf{QR-07}\newline Operational bounds &
Bound input, grammar expansion, parser traces and retained media. No unmeasured
latency, throughput, uptime or concurrency guarantee is claimed. Public tests
have no automatic purge: operators must monitor storage growth.\\
\bottomrule
\end{longtable}

\begin{tabularx}{\linewidth}{@{}L{2.1cm}X@{}}
\toprule\tablehead\textbf{Failure} & \textbf{Required distinction}\\\midrule
403 & Invalid Origin/CSRF or a forbidden reference mutation.\\
404 & Missing resource or an endpoint not exposed in public mode.\\
409 & Stale grammar or conflicting idempotency input, with recovery guidance.\\
413 / 422 & Oversized or structurally invalid input, not successful analysis.\\
429 & Client rate limit exceeded, with \texttt{Retry-After}.\\
503 & Operational/storage/reference failure, explicitly surfaced.\\
CFG rejection & A successfully computed result, not a network failure; it may
be retained as an immutable test.\\
\bottomrule
\end{tabularx}

The default local data root is \texttt{.mboa}; the shared workspace resides under
\nolinkurl{shared-workspace/workspace.sqlite3}. Public rate counters use
\texttt{public-access.sqlite3}, separate from the legacy authentication database.
Deployment uses a persistent directory outside the web root. Public response
redaction does not delete or replace the original stored ownership.

Backups are sensitive recovery artifacts, not evidence of record authorship.
The current shared workspace document format is 5; the outer archive manifest
remains format 1. Backward-compatible migration and validation must preserve
older formats and related media. Same-disk backups are not disaster recovery.
Credentials/configuration require separately protected full-root backup.

cannot be inferred from CSRF protection.

\section{Deployment and Operational Acceptance}
The selected deployment is a single durable Ubuntu VPS, supervised by systemd
and fronted by Nginx. The public address is
\url{https://camfranglais.duckdns.org}; the application listens only on
\texttt{127.0.0.1:2021}. Port 2021 is an internal upstream, not an extra
public-facing URL. HTTPS traffic uses port 443; port 80 supports the configured
HTTP redirect/certificate flow.

SMTP/Google configuration is not required in public mode. The operator shall
preserve existing environment and data, validate Nginx before reload, protect
off-host backups and avoid changing unrelated sites on the shared VPS.
Interactive API documentation is disabled in production. The documentation
session observed the public bootstrap returning HTTP 200 and the direct
no-login browser interface on 27 September; this does not prove long-term
availability, backup recovery or the mechanism used to deploy it.

\section{Submission Gates and Exclusions}
\begin{enumerate}
\item The group shall confirm the true origin and manual-transcription process,
or clearly retain the provenance limitation in the submitted report.
\item The authors shall review original wording, supplied glosses, lexical
ambiguities, the two unresolved tokens and the corpus-specific CFG rationale.
\item The final report shall contain the raw statements, actual token tables,
regex rules, transformations, FIRST/FOLLOW, the complete LL(1) table, parser
results, real screenshots and linguistic discussion.
\item The built report shall measure 25--30 PDF pages, including front matter.
The SRS, SDD and UML atlas are supplementary engineering documents and are
not included in that page limit.
\item The required ten-minute presentation/demo and individual contributions
shall be rehearsed separately. This documentation release does not claim that
slides, oral performance, authenticity or instructor approval are complete.
\end{enumerate}

\notice{Meaning of acceptance}{
Software verification establishes behavior on stated tests and snapshots.
It cannot certify speaker intent, accurate transcription of an unheard event,
fieldwork consent, population-level language coverage or academic approval.}
