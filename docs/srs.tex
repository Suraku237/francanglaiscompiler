\section{Purpose and Document Control}
Mboa supports the CS4110 Compiler Construction SET A assignment, \emph{Lexical
and Syntactic Analysis of Informal Urban Communication in Yaoundé}. The product
combines a deterministic custom lexer and LL(1) compiler laboratory with private
manual collection, local text import and recoverable account/project storage.
It is not an AI translation or conversational service.

Version 3.0 supersedes the active business/AI product scope. Earlier
\nolinkurl{*.legacy.md}, \nolinkurl{srs-legacy.tex},
\nolinkurl{sdd-legacy.tex} and evidence JSON remain historical material;
they are not acceptance of this release. No earlier research or sprint is
retroactively declared complete. The SDD and its source-grounded UML explain
implementation. The root README explains operation; the documentation register
records fresh document validation.

\subsection{Status vocabulary}
\begin{description}[style=nextline]
\item[Implemented capability] A source-level function or user workflow exists.
This alone does not prove correct fieldwork, complete coursework or every
deployment configuration.
\item[Automated evidence] A stated test/build/measurement with controlled
fixtures. Synthetic fixtures never count as real collected statements.
\item[Human gate] Authentic transcription, linguistic interpretation,
consent, final report review, rehearsal or deployment acceptance.
\item[Illustrative material] Supplied references, constructed examples and
the default CFG. These are learning aids, not empirical findings.
\end{description}

\section{Assignment Baseline and Traceability}
The supplied Summer 2026 brief sets the due date to \textbf{29 September 2026}.
Groups contain three students. The final report must be 25--30 pages and must
not exceed 30 pages. A ten-minute PowerPoint presentation and demonstration
allocates three minutes to each member, leaving one shared minute.

Suggested contexts include taxis/commuting, internet connectivity, electricity,
market bargaining, rain, fuel scarcity, roadside business, bendskins,
security and university life. The brief does not require a fabricated example
for every topic.

\section{Product Scope and Actors}
\subsection{Primary roles}
A visitor can register, verify email, sign in and recover an account. A verified
account owner works only inside that account's private projects. Three group
names are assignment metadata, not a shared-team authorization role. There is
no cross-account collaboration, billing or in-app administrator console.

The operator manages the durable host, identity/email configuration and backup
policy. The operator can access underlying files; account isolation is not
end-to-end encryption. SMTP delivers account messages in production. Optional
Google OAuth supplies identity, never language generation.

\subsection{Included and excluded capabilities}
The default authenticated application exposes compiler/coursework workflows,
manual collection, reference dictionary, constructed practice, local document
import, retained history and workspace settings. Accounts, projects, recordings,
revisions and backups remain available.

The product excludes AI generation, chat, translation endpoints, provider
explanations, OCR, remote transcription and browser dictation. Leftover private
\nolinkurl{GEMINI_*} configuration is unused; no model key is required.
Optional browser text-to-speech is read-aloud only, not field transcription or
linguistic evidence. Only voices reported by the browser as
\texttt{localService} are selected, with no remote-voice fallback. Voice
availability and locality reporting depend on the browser/OS; this is not an
application-level guarantee of every underlying network behavior.

The desktop collector and an explicitly unauthenticated maintenance factory
retain compatibility with legacy files. They are separate from normal web
storage. Production refuses to disable authentication.

\section{Functional Requirements}
\begin{longtable}{L{2.0cm}L{12.4cm}}
\toprule\textbf{ID / area} & \textbf{Requirement and measurable acceptance}\\\midrule\endhead
\req{FR-01}{Accounts}
{Require verified email/password access; support explicit optional Google
sign-in/linking and single-use verification/recovery tokens.}
{Unverified password login fails. Invalid/replayed tokens fail. Recovery
revokes previous sessions. Matching Google email alone cannot link an account.}
\req{FR-02}{Sessions}
{Enforce authenticated private APIs, allowed Origin and session-specific CSRF
on mutations. Keep deployment credentials server-side.}
{Missing identity returns 401; invalid Origin/CSRF returns 403. Production
requires secure cookies/HTTPS and refuses no-auth operation.}
\req{FR-03}{Isolation}
{Select the account directory from server-validated identity and bind dataset
and coursework adapters to the current project using request-local contexts.}
{Foreign account/project access cannot expose or mutate statements, profile,
screenshots, audio, history, revisions or backups. Concurrent requests do not
switch one another's storage.}
\req{FR-04}{Projects}
{Create/rename projects, retain General, and allow deletion only when the
project is empty of protected records, including coursework/screenshots.}
{An unknown/foreign project fails. Switching/sign-out warns before discarding
unsaved drafts. Existing accounts are neither deleted nor silently migrated.}
\req{FR-05}{Manual data}
{Preserve exact nonblank raw statements, glosses and notes, including case,
accents, code-mixing and incomplete speech. Store provenance separately.}
{Raw text, glosses and notes are not rewritten. Existing ShortText validation
trims supplied contributor/location values on save, not during import preview.
Duplicates and failed saves are explicit. Only Sentence entries count toward
the 10--15 requirement.}
\req{FR-06}{Review}
{Require explicit human review of annotations. An evidence edit invalidates
prior approval unless the new evidence is explicitly reviewed.}
{Imported records start unreviewed. A change of raw text, language or lexical
annotation cannot silently keep stale approval.}
\req{FR-07}{Recording}
{Allow local browser recording/preview/download and explicit private attachment,
without dictation, transcription or automatic upload on recording alone.}
{Permission/codec failures are actionable; typed/file input remains available.
Private playback honors owner/project selection and HTTP range semantics.}
\req{FR-08}{Import}
{Extract UTF-8 TXT/Markdown/CSV/JSON, DOCX and text-layer PDF locally on the
application server. Show text/warnings/drafts before any save.}
{No generation/provider call occurs. Unsupported/scanned-only inputs fail
explicitly. Structured metadata cannot import an approved status. Extracted
text is bounded and checked against the original by the user. Preview preserves
provenance values; an explicit save applies the short-metadata rule in FR-05.}
\req{FR-09}{References}
{Expose a read-only, source-labelled dictionary and clearly constructed practice
library without populating the real corpus automatically.}
{Search preserves reference file/line and competing senses. Reference origin
is not presented as POS or a French translation; practice is marked constructed.}
\req{FR-10}{Lexer}
{Use a deterministic custom regex/lexicon pipeline for token categories,
multiword verb/slang phrases and code-mixing clues, preserving raw token text.}
{Token tables retain unrecognized symbols as UNKNOWN. Approved unambiguous
Word annotations can extend lookup; Sentence rows do not train a model.}
\req{FR-11}{Corpus metrics}
{Compute frequency, category totals, unknown tokens and observed spelling
variation from the selected project's saved entries.}
{No reference/example rows are injected. Normalized variation groups are
labelled orthographic candidates, not certified semantic equivalence.}
\req{FR-12}{Project profile}
{Save exactly three member strings, manual-transcription confirmation, collection
method, grammar, rationale, discussion and limitations per project.}
{Nonblank member names must be distinct. New profiles use blank members and an
illustrative grammar; missing fieldwork never becomes an automatic ready claim.}
\req{FR-13}{Grammar}
{Parse bounded CFG notation, remove supported direct/indirect left recursion
and left-factor with traceable before/after steps.}
{Invalid notation or excessive transformation work is rejected. Unchanged
stages are explained. The group must justify the grammar against its own data.}
\req{FR-14}{Sets/table}
{Compute FIRST/FOLLOW to a fixed point, including epsilon/end marker, then
construct an LL(1) table with explicit conflicts.}
{Conflicts and residual recursion are surfaced; the implementation does not
arbitrarily select a production to conceal a non-LL(1) grammar.}
\req{FR-15}{Parser}
{Run a bounded table-driven predictive parser over lexical categories, showing
stack, remaining input, selected production/action and acceptance/rejection.}
{Single-input and corpus results use the submitted grammar and actual tokenized
text. Rejection is a grammar-fit result, not a judgment of spoken correctness.}
\req{FR-16}{Screenshots}
{Accept genuine uploaded analyzer captures with bounded decoding, normalization
and private owner/project-scoped byte retrieval.}
{Only allowed image formats/sizes pass. Foreign project/owner reads fail.
Upload/delete increments the workspace version; no fabricated evidence is generated.}
\req{FR-17}{Course export}
{Export a DRAFT HTML report, editable PowerPoint, saved raw data, lexical/grammar/
parser artifacts, screenshot bytes and implementation source snapshots.
Hold the account's shared lock across the profile/corpus/screenshot evidence read.}
{Missing data/discussion is explicit. The 25-section structure is not called
25 printed pages. Concurrent account mutations cannot mix saved evidence
revisions during export. Report/presentation remain human-review tasks.}
\req{FR-18}{Legacy history}
{Keep existing AI-generated translations/conversations readable and exportable
as legacy data without resuming a generation workflow.}
{Upgrading the product does not delete histories or invoke removed endpoints
when viewing/downloading them.}
\req{FR-19}{Recovery}
{Retain revisions, verified backups, bounded scheduling, validation previews,
version checks and a pre-restore safety backup. Include coursework/screenshots.}
{Workspace document format 2 round-trips private data; legacy format 1 remains
restorable. The outer archive manifest stays format 1. Stale previews cannot
overwrite new profile/screenshot changes.}
\req{FR-20}{Non-AI contract}
{Return health status ok with mode compiler. Remove translation/chat/suggestion/
explanation routes and generation settings/quotas.}
{No language-provider client or model configuration is required. Local compiler
and import tests run without external providers; Google HTTP and SMTP remain
separate identity facilities.}
\bottomrule
\end{longtable}

\section{Quality Requirements and Failure Contracts}
\begin{longtable}{L{2.8cm}L{11.6cm}}
\toprule\textbf{ID} & \textbf{Requirement and evidence boundary}\\\midrule\endhead
\textbf{QR-01}\newline Integrity &
Use SQLite transactions and coordinated file locks. Reject stale recovery
versions, invalid identifiers, unsafe archive paths and invalid media. Filesystem
and SQLite operations are coordinated, not a distributed ACID transaction.
Failures must not be reported as successful persistence.\\\addlinespace
\textbf{QR-02}\newline Privacy &
No field data or source code is sent to a generation provider or online diagram
renderer. Private account storage remains outside public assets. Protect session/
email/OAuth secrets and avoid query-string logging. The server/operator remains
inside the trust boundary.\\\addlinespace
\textbf{QR-03}\newline Explainability &
Expose rules, transformation steps, sets, table conflicts, traces and lexical
limitations. Natural-language explanations are authored by students, not generated.
A passing parse is not evidence of real-world authenticity.\\\addlinespace
\textbf{QR-04}\newline Responsiveness &
Bound file, corpus, grammar and trace work; preserve cancellation/stale-response
protection in the UI. Report measured timings with machine, fixture, warm-up,
sample count and limitations, never borrowed historical performance claims.\\\addlinespace
\textbf{QR-05}\newline Accessibility &
Retain labelled forms, keyboard actions, focus-managed dialogs, visible errors
and text/file alternatives to microphone functions. Test desktop/mobile layouts;
mocked checks alone do not certify every browser, device or assistive technology.\\\addlinespace
\textbf{QR-06}\newline Maintainability &
Use existing test/build tools. Cover all authored production classes in UML with
actual methods/relationships. Validate every sequence activation, atlas mapping,
image fingerprint and clean LaTeX references/layout after rebuilding.\\
\bottomrule
\end{longtable}

Validation errors use actionable messages and bounded inputs. Authentication,
authorization, conflict, missing-resource and storage failures remain distinct;
provider availability is not a compiler failure category. A failed PDF import
must request a supported/manual transcript rather than silently fabricate text.

These are storage/processing limits, not assignment targets or certified load
capacity. Deletion may leave older revisions/backups until their explicit
retention policy removes them. Unreferenced recordings are not silently erased.
The screenshot route allows a 3 MiB JSON body for base64 transport; the generic
JSON cap remains 1 MiB. Coursework exports contain screenshot bytes but do not
bundle raw recordings; full workspace backups preserve recordings and coursework
together.

\subsection{Backup compatibility}
The workspace document advances to format 2 to include coursework and screenshots.
Restoring format 1 remains supported without those newer collections. The outer
ZIP manifest remains format 1. Every new coursework/screenshot mutation must
advance the workspace version so a preview cannot overwrite unseen changes.
Restore validates logical records, stages safe media, creates a safety backup
and commits under the selected account lock.

Backups omit authentication secrets and server configuration. The operator must
protect and rehearse a separate consistent backup of the full data root,
including the identity database. Same-disk workspace ZIPs cannot recover a lost
host or recreate account identities on their own.

\section{Interfaces and Operating Constraints}
The browser uses same-origin HTTP APIs served by FastAPI alongside the built
React application. Private calls carry a session cookie; mutations additionally
require Origin/CSRF. A validated project header selects request scope; private
native audio/image URLs can carry a project query parameter.

Local operation uses loopback and a private file-mail outbox unless SMTP is
configured. Production requires an HTTPS public origin, secure cookies, actual
SMTP and durable private storage behind a trusted reverse proxy; interactive
API docs are disabled. Google remains optional. The supported topology is one
durable application host, not a stateless/multi-host SQLite cluster.

\section{Acceptance Strategy and Completion Gates}
\subsection{Software verification}
Fresh backend/compiler, frontend and browser results must name exact commands,
fixtures and outcomes. Unit tests use synthetic data and isolated storage;
browser tests exercise the built application. Compiler measurements must identify
the measured workload and exclusions. The documentation build must render all
current diagrams, compile atlas/SRS/SDD, and pass the strict checker without
layout/reference warnings. Earlier evidence JSON stays historical and unmodified.

\subsection{Fieldwork and report gates}
\begin{enumerate}
\item Receive 10--15 genuine manual transcriptions and record provenance,
collection method, consent/anonymization and all three member contributions.
\item Review exact raw text and lexical labels, including unknowns, multiword
phrases, code-mixing and frequency/variation interpretations.
\item Construct and justify the CFG from those observations; examine
transformation logs, FIRST/FOLLOW, conflicts and own-data accepted/rejected cases.
\item Attach genuine analyzer screenshots and author the linguistic discussion:
mixing, slang, context, incomplete speech and limits of the chosen formal grammar.
\item Export the draft and check actual printed pagination: 25--30 pages,
never over 30. The engineering SRS/SDD are not that report.
\item Rehearse the ten-minute demo with three minutes per member and a shared
minute. Only the group/instructor can approve submission readiness.
\end{enumerate}

\notice{No premature completion claim}{
Empty data, an illustrative CFG, synthetic test passes or a generated draft
cannot satisfy real collection and linguistic analysis. The product deliberately
keeps authenticity, report pagination and presentation rehearsal as human gates.}
