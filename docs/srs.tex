\section{Introduction and Document Control}
\subsection{Purpose and audience}
This SRS defines the expected behavior, quality constraints and delivery
backlogs of the Francanglais (Camfranglais) platform. It supports contributors,
the project group, reviewers and testers. It accompanies the Software Design
Description (SDD), which explains the architecture and UML workflows.

\subsection{Evidence and requirement status}
The baseline is grounded in \nolinkurl{data_collector/App.py},
\nolinkurl{data_collector/dataset.py} and
\nolinkurl{data_collector/audio_utils.py}. The root README describes later
language-analysis ambitions. The coursework JSON contains an explicitly
illustrative grammar, not a validated corpus grammar.

\begin{longtable}{L{1.7cm}L{12.4cm}}
\toprule
\textbf{Status} & \textbf{Meaning throughout this document}\\ \midrule
\endhead
B & Baseline behavior is supported by available source. This is not a claim that every acceptance test has been executed.\\
T & Target requirement or proposed enhancement; implementation or release-level verification is still required.\\
D & Deferred enhancement, retained in the product backlog but not committed to the four-sprint proposal.\\
\bottomrule
\end{longtable}

Compiled frontend assets and Python caches do not establish a supported
backend API or a complete compiler implementation. No HTTP route, classifier
accuracy, completed sprint or measured team velocity is inferred from them.
This revision adds acceptance criteria, user stories, a prioritized product
backlog and four sprint backlogs to the initial specification.

\subsection{Definitions}
\begin{description}[style=nextline]
\item[Entry] A word, phrase or sentence with annotation fields and optional audio.
\item[Gloss] A contributor-supplied meaning in standard French or English.
\item[Backlog item] A prioritized unit of product work, identified by PB.
\item[User story] An actor goal, its benefit and acceptance criteria, identified by US.
\item[Story point (SP)] A relative complexity estimate; it is not an hour or a measured velocity.
\item[Sprint backlog] Selected product items and the concrete tasks proposed for one two-week iteration.
\end{description}

\section{Overall Description}
\subsection{Product scope}
The implemented product is a single-workstation desktop collector with Collect,
Browse \& Edit, and Stats tabs. It stores UTF-8 CSV data and local audio files.
It has no authentication or concurrent-writer coordination. Contributor and
maintainer are usage roles, not enforced permission levels.

The proposed next increment consumes corpus evidence to tokenize input,
classify tokens and explain sentence-level analysis. It must remain separate
from data-entry operations. A future predictor for unseen words is deferred.
A web service, automatic transcription, production linguistic accuracy and
multi-user database deployment are outside the four-sprint commitment.

\subsection{Stakeholders and environment}
\begin{itemize}
\item \textbf{Contributor}: captures linguistic examples and optional recordings.
\item \textbf{Maintainer}: corrects annotations, removes unwanted rows and checks corpus coverage.
\item \textbf{Learner/analysis user}: requests the proposed language-analysis results.
\item \textbf{Project group/reviewer}: verifies acceptance evidence and documentation.
\end{itemize}
Python, CustomTkinter and Tcl/Tk provide the desktop UI. NumPy, sounddevice,
soundfile and a working PortAudio/device environment support recording.
Attaching an existing file does not require a working microphone.
The current workstation is Windows; platform playback branches are not proof
of tested support on every operating system.

\section{Functional Requirements}
The acceptance checks below are the required verification outcomes. Baseline
rows describe existing behavior accurately; target rows must not be read as
already implemented.

\begin{longtable}{L{1.8cm}L{12.5cm}}
\toprule
\textbf{ID}\newline\textbf{Status} & \textbf{Requirement and acceptance check}\\ \midrule
\endhead
\requirement{FR-01}{B}
{The system shall initialize the managed audio directory and create the CSV header if the dataset is absent.}
{Start with missing storage: both are created. Start with existing data: rows and header remain unchanged.}
\requirement{FR-02}{B}
{Saving shall reject text that is empty after surrounding whitespace is removed.}
{Submit spaces or blank text: show ``Missing text'' and append no row. Non-empty text can proceed.}
\requirement{FR-03}{B}
{The collector shall offer word, phrase and sentence entry types and the ten defined categories.}
{Each option is selectable and the chosen value is stored; defaults are word and greeting after a form reset.}
\requirement{FR-04}{B}
{The collector shall accept optional French gloss, English gloss, notes and contributor text. Category and type use selection controls.}
{Save with blank optional fields and again with annotations; values round-trip without making glosses mandatory.}
\requirement{FR-05}{B}
{A new row shall receive a generated ten-character hexadecimal UUID-derived ID and a local ISO-8601 timestamp with seconds.}
{Verify format on insertion and that editing preserves ID and timestamp. Collision prevention is not implemented.}
\requirement{FR-06}{B}
{Saving shall append one UTF-8 CSV row using the ten-field schema. Updating or deleting shall rewrite the canonical header and retained rows.}
{Read the file with a CSV parser after each operation; field order and unrelated rows are preserved.}
\requirement{FR-07}{B}
{The Collect tab shall show an advisory duplicate warning for equal text after strip/lower normalization, scheduled after 400 ms of typing inactivity.}
{A case/outer-space variant warns; a distinct value clears the warning. A duplicate can still be saved; it is not a uniqueness rule.}
\requirement{FR-08}{B}
{When recording support and a microphone work, Record/Stop shall capture mono audio at 44,100 Hz and stage a WAV filename.}
{Capture frames, stop and verify the WAV. With no frames, show ``No audio captured'' and create no new recording.}
\requirement{FR-09}{B}
{The contributor shall be able to choose an existing audio file or cancel the chooser without changing the draft.}
{Select a file to stage its copy; cancel and verify the previous pending filename remains unchanged.}
\requirement{FR-10}{B}
{New recordings and attachments shall use generated filenames inside the managed audio directory; attachments preserve the original extension.}
{Verify the copied/recorded file and the saved row's filename. The original attached file is not modified.}
\requirement{FR-11}{B}
{Browse shall filter rows using a case-insensitive substring of text, category or contributor and populate the editor from a selected cached row.}
{An empty query lists all rows, a non-match lists none, and selection displays the corresponding metadata without a second read in the selection handler.}
\requirement{FR-12}{B}
{A selected entry shall support editing text, type, category, both glosses and notes, or deletion from the CSV.}
{An edit changes only the allowed fields; deletion removes matching ID rows. The ID, contributor, timestamp and audio filename are not editable here.}
\requirement{FR-13}{B}
{Pending or selected audio shall be playable through the audio libraries, with an OS-player fallback when unavailable or unsuccessful.}
{A missing file returns failure; a failed library attempt can reach the OS fallback; failure of both paths produces the GUI error dialog.}
\requirement{FR-14}{B}
{An explicit Stats refresh shall show total rows and descending counts/bars by entry type and category.}
{Compare with a known fixture; empty data shows zero total and ``No data yet.'' No divide-by-zero occurs.}
\requirement{FR-15}{T}
{The proposed analysis increment shall accept text and return tokens, token labels with evidence, and a sentence-analysis status with diagnostics.}
{Approved mixed-language fixtures yield reproducible structured results; empty/unsupported input has explicit diagnostics rather than fabricated success.}
\requirement{FR-16}{T}
{Analysis shall be read-only with respect to the source dataset and audio.}
{File hashes before and after successful and rejected analysis requests are identical. New predictions are not automatically inserted.}
\requirement{FR-17}{B}
{After a successful save, the collector shall refresh count/recent entries and clear the draft while retaining contributor. Escape also retains contributor; Clear may remove it.}
{Verify the latest six rows appear newest-first, form defaults reset, pending audio clears, and the contributor follows the invoked reset action.}
\requirement{FR-18}{B}
{Edit/delete without a selection shall show an information message; deletion of a selection shall require Yes/No confirmation.}
{No selection or No leaves the CSV unchanged; Yes removes the row and clears the selected ID/audio reference. The audio file itself remains.}
\requirement{FR-19}{T}
{A failed CSV mutation shall preserve the last valid dataset and report an actionable error instead of showing saved/deleted success.}
{Inject write/replace failures: the prior file remains parseable and byte-identical, and the UI reports the failure. Current direct rewrites do not satisfy this target.}
\requirement{FR-20}{D}
{A future unknown-word predictor shall distinguish speculative candidates from corpus-confirmed entries and provide its evidence or abstain.}
{Unseen-token fixtures never appear as confirmed corpus facts; prediction does not mutate the dataset. No accuracy claim is made without evaluation.}
\bottomrule
\end{longtable}

\requirement{NFR-01}{B}
{The desktop shall enforce a minimum window size of 760 by 620 pixels and offer Ctrl+Enter for Save and Escape for clearing the draft.}
{Resize and exercise all tabs/shortcuts; record any clipped essential controls as a release defect.}

{Mock missing files and library/OS exceptions; failure returns false and displays an error. True means request accepted, not sound heard to completion.}
\requirement{NFR-04}{B}
{Managed paths shall be based on the collector directory and generated media filenames, not persistent links to user-selected source files.}

\requirement{NFR-05}{B}
{Failure to import optional audio dependencies shall disable live recording without preventing text collection, browsing or file attachment.}
{Run a dependency-unavailable fixture and verify those non-recording operations. Device-open failures are a separate robustness concern.}
\requirement{NFR-06}{T}
{Analysis shall be deterministic for a fixed corpus, grammar and rule configuration.}
{Repeat each golden fixture ten times and compare serialized tokens, labels and diagnostics, excluding intentionally variable request metadata.}
\requirement{NFR-07}{T}
{Critical collector paths shall have automated regression tests using isolated temporary data and mocked audio hardware.}
{All approved CRUD, validation, duplicate, fallback and failure cases pass without modifying the team's real corpus. No test suite completion is assumed.}
\requirement{NFR-08}{T}
{Submission artifacts shall exclude credentials and raw personal recordings unless explicitly approved for release. Collection and sharing shall follow documented consent.}
{Review exported files and repository exclusions; retain consent/approval evidence separately with restricted access. Ignoring a file does not remove it from old history.}
\requirement{NFR-09}{B}
{Documentation shall build locally from LaTeX and PlantUML sources with reproducible diagram references and readable PDFs.}
{Render every UML source, compile both documents, and check images, references, table layout and placeholders using the documented commands.}
\requirement{NFR-10}{T}
{On a recorded reference Windows workstation with 8 GB RAM and local SSD, search and Stats refresh shall each have p95 latency at most 1 second for 1,000 rows of up to 500 text characters.}
{Measure 20 warm runs per operation after one warm-up, excluding audio capture; report hardware/runtime and the nearest-rank 95th percentile. This target is not benchmarked here.}
\requirement{NFR-11}{T}
{CSV updates shall use failure-safe replacement, and recording/device failures shall produce useful feedback without a false success status.}
{Fault-inject disk and audio-device failures; preserve valid data, permit retry, and record the visible diagnostic. Baseline writes and recording handlers have gaps.}
\requirement{NFR-12}{T}
{The team shall maintain a manual backup/restore procedure for the CSV and referenced audio; backup copies shall have restricted access.}
{Restore a fixture backup to a separate directory and compare all rows and referenced-file hashes. No backup button is claimed.}

\section{User Stories and Acceptance Criteria}
The stories describe desired user value. B stories still need the proposed
regression evidence; T and D stories require additional development. Each
story maps to exactly one product backlog item with the same numeric suffix.

\story{US-01}{Initialize a usable corpus}
{As a contributor, I want storage initialized without overwriting existing entries so that I can safely start or resume collection.}
{FR-01, FR-06, NFR-02, NFR-04}
{\item Given absent storage, launch creates the canonical header and audio directory.
\item Given existing UTF-8 rows, relaunch preserves them byte-for-byte until an explicit mutation.}

\story{US-02}{Capture an annotated example}
{As a contributor, I want to save a word, phrase or sentence with optional meanings and context so that the corpus retains useful linguistic evidence.}
{FR-02--FR-06, FR-17, NFR-01}
{\item Blank/whitespace text is rejected without a new row.
\item Valid text with either blank or completed optional annotations saves with generated ID/time and chosen type/category.
\item A successful save refreshes recent/count displays and resets the draft while retaining contributor.}

\story{US-03}{Notice duplicate text}
{As a contributor, I want a duplicate warning so that I can review repetitions without losing the ability to record legitimate variants.}
{FR-07}
{\item A strip/lower-equivalent existing text warns after the typing debounce.
\item Changing to distinct text clears the warning; ignoring it does not block saving.}

\story{US-04}{Find and select an entry}
{As a maintainer, I want to search text, category or contributor so that I can quickly locate an entry for review.}
{FR-11, NFR-10}
{\item Case variants of a matching query return the same matching rows.
\item Empty/non-matching queries show all/no rows respectively.
\item Selecting a displayed row loads its own fields and audio availability.}

\story{US-05}{Correct an annotation}
{As a maintainer, I want to edit selected linguistic fields so that mistakes can be corrected without changing entry identity.}
{FR-06, FR-12, FR-18}
{\item No selection or blank replacement text produces a message and no write.
\item A valid edit survives reload; ID, timestamp, contributor and audio reference stay unchanged.}

\story{US-06}{Delete with confirmation}
{As a maintainer, I want confirmation before deleting an entry so that a mistaken click does not remove corpus data.}
{FR-12, FR-18}
{\item No selection or a No response leaves the file unchanged.
\item Yes removes matching ID rows, clears the selected reference and refreshes the display.
\item The associated audio file remains available for separately managed cleanup.}

\story{US-07}{Attach existing audio}
{As a contributor, I want to attach a recording from disk so that I can contribute audio without a working microphone.}
{FR-09, FR-10, NFR-04, NFR-05}
{\item Selection copies the source under a generated filename with its extension.
\item Cancellation changes neither the draft attachment nor the original file.
\item Saving the draft links the staged filename to the new row.}

\story{US-08}{Listen to an example}
{As a contributor, I want to play pending or stored audio so that I can check the recording linked to an entry.}
{FR-13, NFR-03}
{\item Library playback is attempted when available; a failure can fall back to the OS player.
\item A missing file or rejected fallback shows a playback error, not a success message.
\item Playback never modifies CSV rows.}

\story{US-09}{Record an example}
{As a contributor, I want to record and stop microphone audio so that a pronunciation example can accompany the text.}
{FR-08, FR-10, NFR-05, NFR-11}
{\item A working recorder produces a mono 44,100 Hz WAV and stages its filename.
\item No frames produce a visible empty-capture message and no new WAV.
\item Missing dependencies disable recording; device-failure feedback is target hardening, not baseline behavior.}

\story{US-10}{Review corpus coverage}
{As a maintainer, I want total/type/category statistics so that I can identify underrepresented categories during collection.}
{FR-14, NFR-10}
{\item A refresh matches independently calculated fixture totals and groups.
\item Empty data shows zero/no-data labels, and bars never divide by zero.}

\story{US-11}{Protect corpus quality and privacy}
{As a maintainer, I want regression checks, safe writes and a recovery procedure so that the team's data remains usable and appropriately protected.}
{FR-19, NFR-07, NFR-08, NFR-10--NFR-12}
{\item Injected CSV write failures preserve the last valid file and report an error.
\item Regression/performance reports use fixtures, not personal recordings.
\item A documented backup restores with matching rows and audio hashes; publication has approval.}

\story{US-12}{Build understandable documentation}
{As a group member, I want editable UML and LaTeX documents with explanations so that the design and requirements can be reviewed and reproduced.}
{NFR-09}
{\item Every diagram has a source, rendered image, explanation and trace to a feature.
\item Both PDFs compile with no unresolved references or overflowing tables.
\item The group can fill its names/matricules without changing system requirements.}

\story{US-13}{Inspect lexical analysis}
{As a learner, I want tokenization and evidence-based labels so that I can see how mixed-language input relates to the corpus.}
{FR-15, FR-16, NFR-06}
{\item Approved fixtures produce tokens with labels and evidence; unknowns remain explicit.
\item Repeated analysis is deterministic and leaves corpus/audio hashes unchanged.}

\story{US-14}{Inspect sentence analysis}
{As a learner, I want sentence status and explanatory diagnostics so that I can understand the limits of the declared analysis rules.}
{FR-15, FR-16, NFR-06}
{\item Valid and rejected teaching examples return an explicit status and reason.
\item The selected grammar/rule version is identified; the starter grammar is not presented as a validated description of all Camfranglais.
\item Empty and unsupported input is handled explicitly without modifying evidence.}

\story{US-15}{Receive a demonstrable release}
{As a reviewer, I want a repeatable end-to-end demonstration and acceptance report so that I can distinguish verified outcomes from unfinished features.}
{FR-15, FR-16, FR-19, NFR-07--NFR-12}
{\item The selected collector and analysis stories pass their approved acceptance checks.
\item The handover includes built PDFs, test/performance evidence, recovery steps and an honest known-limitations list.
\item Every completed claim points to evidence; unfinished work stays in the backlog.}

\story{US-16}{Explore unseen-word candidates}
{As a learner, I want speculative candidate explanations for unknown words so that I can explore possible blends without mistaking a guess for a corpus fact.}
{FR-20, FR-16, NFR-06}
{\item Predictions are labelled speculative with evidence or abstention.
\item No automatic insertion or unevaluated accuracy claim is made.
\item This story remains deferred beyond the four proposed sprints.}

\subsection{Definition of Ready, Done and change control}
\textbf{Ready:} actor value, requirement links, acceptance criteria, dependency
availability, fixture data/consent, estimate and lead are agreed before work starts.
\textbf{Done:} implementation is reviewed, applicable automated/manual tests
pass, acceptance evidence is recorded, documentation is current, and no
known critical data-loss or privacy issue remains in the selected scope.

Use Planned, In progress, Blocked and Done states on the team's board. Review
progress daily; hold a demonstration and retrospective after each sprint.
At each boundary, re-estimate remaining work and update dependencies and
totals. A source-supported feature is not retroactively a completed sprint.
New scope is prioritized in the product backlog before entering a sprint.

\section{Constraints, Risks and Open Decisions}
\begin{itemize}
\item CSV writes are currently non-atomic and uncoordinated. The baseline is
single-writer only; FR-19/NFR-11 are planned safeguards, not current guarantees.
\item Truncated UUID IDs are generated, not collision-checked. External CSV
edits can introduce duplicate IDs, invalid categories or missing media links.
\item Recording depends on working hardware. Long recordings are buffered
in memory with no stated duration limit; large-audio scaling is not promised.
\item Compiler fixtures, language labels and teaching rules require team
review. The illustrative grammar cannot validate all language varieties.
\item Estimates, dates, member identities and actual task acceptance need
team confirmation. Only the four two-week sprint structure has been selected.
\item Multi-user services, authentication, speech-to-text and prediction
accuracy remain future scope unless the backlog is explicitly re-approved.
\end{itemize}
